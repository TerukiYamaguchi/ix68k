# sram_switch

バージョン 1.0（`sram_switch --version` で表示）。

`sram.dat`（オフライン）のメモリスイッチ設定ツール（C99 / 依存なし）。

実機の `SWITCH.X` と同じ `KEY=VALUE` 形式で、エミュレータを起動せずに `sram.dat` を
読み書きする。**オフライン専用**: エミュレータ起動中に書き換えても、終了時に
`x68k_bus_save_sram()` が現在のメモリ上の値で上書き保存するため反映されない。
起動中の値を見る/変えるには MCP `read_memory`/`write_memory`（`$ED0000`〜）を使う
（`tools-host/mcp/MCP_TOOLS.md` 参照）。

`sram.dat` はファイル先頭が物理 `$ED0000` に対応する 16KB の生ダンプ（ヘッダなし）。
アドレスは `local/refs/XC20_ProgManual_appendix.md`（Human68k ProgManual 付録）に基づく。

## ビルド

```sh
make            # → ./sram_switch
```

Windows は CMake（`cmake --build build --target sram_switch`）で `sram_switch.exe` を作る。

## 使い方

```sh
sram_switch                          # sram.dat の現在値を表示
sram_switch -f other.dat             # ファイル指定して表示
sram_switch B=2HD0                   # 起動デバイスをFD0に設定
sram_switch B=SCSI0                  # 起動デバイスをSCSI ID0に設定（$ED000C も同時更新）
sram_switch -f other.dat S=Program 'P1=$F83E'
```

引数なしで現在値一覧を表示（読み取り専用、書き込みなし）。`KEY=VALUE` を1つ以上
指定すると設定を書き換えて保存する。保存前に `<file>.bak` へ自動バックアップする。

|------|------|----|--------------|

| `M` | `MEMORY` | メモリサイズ（KB、例: `2048`） | `$ED0008` |
| `E` | `EJECT` | `On` / `Off`（電源OFF時の自動イジェクト） | `$ED0029` |
| `O` | `OPT2KEY` | `Tvctrl` / `Normal` | `$ED0027` |
| `C` | `CONTRAST` | `0`〜`15` | `$ED0028` |
| `K` | `KANA` | `Jis` / `Aiu` | `$ED002B` |
| `L` | `LCD_MODE` | `Lcd` / `Normal` | `$ED002C` |
| `S` | `SRAM` | `No_use` / `Ramdisk` / `Program`（`N`/`R`/`P`） | `$ED002D` |
| `P0`〜`P4`, `P8` | — | `$0000`〜`$FFFF`（GRB555、テキストパレット） | `$ED002E`〜`$ED0038` |

| `X` | `XCHG` | `0`〜`7`（キー入れ替え設定、bit0-2） | `$ED0059` |
| `HD_MAX` | — | `0`〜`16`（内蔵SASI HDCのドライブ数上限。`HD<n>`起動を機能させるのに必須） | `$ED005A` |

| `R` | — | `<baud>,<bits>,<parity>,<stop>,<flow>`（例: `9600,8,N,1,X`） | `$ED001A` |

### `B=`（起動デバイス）の詳細（Issue #112）

`$ED0018`単独では起動先を一意に決められないキーがある（`SCSI*`/`ROM*`は`$ED000C`、
`RAM*`は`$ED0010`の値も見て初めて決まる）。書き込み時はこれらの従属フィールドも
同時に更新し、表示（`show()`/書き込み後の確認出力）は`$ED000C`/`$ED0010`まで見て
一意な文字列に復元する。「表示された文字列をそのまま`B=`に渡すとSRAMが変化しない」
という往復性を保証している。

- `SCSI0`〜`SCSI6`: `$ED0018=$A000`＋`$ED000C=$FC0000+id*4`（内蔵SCSI BIOS ROM、
  `.HDS`起動の正規経路）。`SCSI7`はID7が本体ホストIDのため実機`SWITCH.X`本体も拒否
  （エラーになる）。
- `HD0`〜`HD15`: `$ED0018=$8000+n*$100`（本体組み込みSASI HDC直接起動）。**`.HDS`とは
  ディスクレイアウトが非互換で起動できない**（警告を表示した上で書き込みは行う、
  実機`SWITCH.X`同様に値自体は有効なため）。`n`はSASI IDではなく論理ドライブ番号
  （`SASI ID = n/2`、`LUN = n%2`）。
- `ROM`（引数省略時`$00BFFFFC`）/ `ROM$<16進アドレス>`: `$ED0018=$A000`＋
  `$ED000C=<アドレス>`。
- `RAM`（引数省略時`$00ED0100`）/ `RAM$<16進アドレス>`: `$ED0018=$B000`＋
  `$ED0010=<アドレス>`。

一次資料（IPLROM XVI逆アセンブル・`SWITCH.X`逆アセンブル・内蔵SCSI BIOS ROM実体・
参照実装XEiJ）はソース冒頭コメント参照。

### `ID=`（SCSI本体ID）の詳細（Issue #115）

実機`SWITCH.X`は内蔵/外付けSCSIボードをハードウェア検出し、`ID=O<n>`構文で外付け
ボード指定を許可した上で`$ED000C`のベースを`$FC0000`⇔`$EA0020`間で切り替えるが、
ix68kは内蔵SCSIのみ実装（拡張ボードCZ-6BS1は`docs/ix68k-internals/design/scsi_design.md`
で非スコープと明記）のため、本ツールは`ID=0`〜`ID=7`（内蔵のみ）を受理し`O`構文は
実装しない。

マジックバイト（`$ED006F=$56`）が未設定の場合のみ、実機と同様に`$ED0071`（ID別ブート
禁止ビットマップ）を`$00`に初期化する。設定済みの場合は既存の`$ED0071`の値を保持する。

### `R=`（RS232C）の詳細（Issue #115）

`$ED001A`（ワード）のビットフィールドはSWITCH.X逆アセンブル（値設定パーサー本体
L000c1e-L000da6）に基づく:

| ビット | 意味 | 値 |
|---|---|---|
| bit0-3 | ボーレート | `0`=75, `1`=150, `2`=300, `3`=600, `4`=1200, `5`=2400, `6`=4800, `7`=9600, `8`=19200 |
| bit7 | RS/CS制御 | 0=無効, 1=有効 |
| bit9 | Xon/Xoff制御 | 0=無効, 1=有効 |
| bit10-11 | データビット | `0`=5, `1`=6, `2`=7, `3`=8 |
| bit12-13 | パリティ | `0`=None, `1`=Odd, `3`=Even |
| bit14-15 | ストップビット | `1`=1, `3`=2 |

実機は`-R-0`〜`-R-5`で複数RS232Cポート（`$ED001A`/`$ED005C`/`$ED005E`/`$ED0060`/
`$ED0062`）を選択でき、実機ドライバ（`232C1.11`）への問い合わせで書き込み先を動的に
決めるが、問い合わせ失敗時（実機接続なし）は`$ED001A`に固定される。本ツールは
オフラインでハードウェア問い合わせを再現できないため、常に`$ED001A`のみを対象とする。

また実機は`9600bps Bits-8 Parity-None Stop-1 Xon`のような順不同・省略可能なトークン列
を許すパーサーだが、本ツールは固定順カンマ区切り`R=<baud>,<bits>,<parity>,<stop>,<flow>`
（全5フィールド必須）のみ受理する（実装・パース双方の単純化を優先）。

## 検証済み（2026-08-15）

- `-Wall -Wextra -std=c99` 警告ゼロでビルド
- `B=SCSI0`〜`SCSI6`が`$ED0018=$A000`＋`$ED000C=$FC0000+id*4`に正しくエンコードされ、
  表示（decode）でも`SCSI<id>`に一意復元されることを確認（Issue #112: 旧実装の
  `SCSI0=0x8000`は誤りだった）
- `B=SCSI7`・範囲外`HD`/`2HD`番号・範囲外`ROM$`/`RAM$`アドレスがエラーになり
  ファイルが変更されないことを確認
- `B=SCSI9 M=4096`のように複数キーの一部が失敗した場合、ファイルが一切変更
  されない（部分適用が起きない）ことを確認
- コピーファイルへの書き込み（`B=2HD0 P1=$1234 M=4096`）・反映・`.bak` 自動生成を確認
- 範囲外値（`C=99`）・未対応キー（`R=`）・存在しないファイル指定のエラー処理を確認

## 検証済み（2026-08-17、Issue #115）

- `HD_MAX=5 X=3 ID=2`が`$ED005A`/`$ED0059`/`$ED0070`に正しく書き込まれ、`ID=2`設定時に
  マジックバイト未設定だったため`$ED006F=$56`・`$ED0071=$00`も併せて書き込まれることを確認
- マジックバイト設定済みの状態で`ID=6`を再設定しても、既存の`$ED0071`の値が保持される
  （上書きされない）ことを確認
- 範囲外値（`HD_MAX=17`・`X=8`・`ID=8`）がエラーになりファイルが変更されないことを確認
- `R=9600,8,N,1,X`が`$ED001A=$4E07`に、`R=19200,7,E,2,R`が`$ED001A=$F888`に正しく
  エンコードされ、表示（decode）でも同じ文字列に一意復元される（往復性）ことを確認
- `R=`のフィールド不足（`R=9600,8,N`）・余分なフィールド・不正値（`R=38400,8,N,1,X`）が
  それぞれエラーになりファイルが変更されないことを確認
