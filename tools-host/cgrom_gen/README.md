# cgrom_gen — 互換CGROM生成ツール

バージョン 2.0（`--version` で表示）。

X68000実機のCGROM（キャラクタジェネレータROM）は著作権上フリー配布されていない。
本ツールは、ユーザー手元のビットマップフォント（BDF形式）から実機互換のCGROMバイナリ
（768KB）をその場で合成する。**フォント自体はこのリポジトリに同梱しない**
（配布するのは本ツールだけで、フォントは各自が用意する）。

C99で書かれ、外部ライブラリに依存しない（PythonもFreeTypeも要らない）。

> バージョン1.0はTTF/OTF/TTCのアウトラインフォントをPythonとPillowで描画していた。
> 2.0はBDFだけを読む。極小サイズでは、手打ちのドットを持つビットマップフォントのほうが
> 読みやすいため。

## クリーンルームであることについて

アドレス配置・ビットパッキング仕様は『インサイドX68000』（アスキー出版局）4章
「CGROM」（p.218-226、図39〜図46）から直接書き起こした。WinX68k/XM6Util等、既存の
CGROM合成ツールのソースコードは一切参照・移植していない（ライセンス不明瞭なコードを
混入させないため）。日本語BDFのENCODINGはJIS X 0208の区点コードそのものなので、
文字コードの変換表も持たない。

## ビルド

リリースZIPには、ビルド済みの`cgrom_gen`（Windowsは`cgrom_gen.exe`）が入っている。
ソースから作る場合:

```sh
make -C tools-host/cgrom_gen          # tools-host/cgrom_gen/cgrom_gen ができる
```

CMakeを使う場合は、リポジトリ全体のビルドで`cgrom_gen`ターゲットも作られる
（Windowsはこちら）。

## 使い方

```sh
# 東雲フォント（下記）から、16x16漢字と8x16半角だけ作る例
cgrom_gen \
  --k16 shinonome-0.9.11/bdf/shnmk16.bdf \
  --a8x16 shinonome-0.9.11/bdf/shnm8x16r.bdf \
  --output rom/CGROM_GEN.DAT
```

出力は必ず786432バイト（`0xC0000`）。1秒もかからない。`ix68k.cfg`では次のように指定する。

```
cgrom = rom/CGROM_GEN.DAT
```

### オプション

サイズごとにBDFを指定する。**BDFのセル（`FONTBOUNDINGBOX`）の大きさは、指定するサイズと
一致させる**（一致しなければエラーで止まる）。

| オプション | サイズ | 対象 |
|---|---|---|
| `--k16 <BDF>` | 16x16 | 漢字（JIS X 0208。非漢字752＋第一水準3008＋第二水準3478） |
| `--k24 <BDF>` | 24x24 | 漢字（同上） |
| `--a8x8 <BDF>` | 8x8 | 半角（ANK） |
| `--a8x16 <BDF>` | 8x16 | 半角（ANK） |
| `--a12x12 <BDF>` | 12x12 | 半角（ANK） |
| `--a12x24 <BDF>` | 12x24 | 半角（ANK） |
| `--output <path>` | | 出力先（必須） |
| `-v` | | サイズごとの取り込み文字数を表示 |

- **指定しなかったサイズは空白のまま出力する**。そのサイズの文字は画面に出ない。
  1つ以上のBDFを指定する必要がある。
- 同じオプションは4回まで繰り返せる。後に指定したBDFが、前のBDFを上書きする。
- 取り込むのは、半角が`0x20`〜`0x7E`（英数記号）と`0xA1`〜`0xDF`（半角カタカナ）、
  漢字がJIS X 0208の定義済み区点。ほかの文字コードは読み飛ばす。
- BDFの`CHARSET_REGISTRY`が`ISO8859`で始まる半角BDFは、`0xA1`〜`0xDF`を取り込まない
  （ラテン1補助文字であり、半角カタカナではないため）。JIS X 0201のBDFなら半角カタカナを
  取り込み、`0x5C`は`¥`、`0x7E`はオーバーラインになる。
- 漢字のENCODINGは、JIS区点コード（`0x2121`〜）と、最上位ビットを立てたEUC形式（`0xA1A1`〜）の
  どちらでもよい。

## フォントの入手

### 東雲フォント

`shinonome-0.9.11p1.tar.bz2`（Electronic Font Open Laboratory、パブリックドメイン）の`bdf/`に、
BDFがある。ダウンロード先: <http://openlab.jp/efont/dist/shinonome/shinonome-0.9.11p1.tar.bz2>

| 用途 | ファイル | セル |
|---|---|---|
| 16x16漢字（ゴシック） | `shnmk16.bdf` | 16x16 |
| 16x16漢字（明朝） | `shnmk16min.bdf` | 16x16 |
| 8x16半角（JIS X 0201、半角カタカナを含む） | `shnm8x16r.bdf` | 8x16 |
| 8x16半角（ISO 8859-1） | `shnm8x16a.bdf` | 8x16 |

東雲フォントには、半角用の8x8・12x12・12x24と、漢字用の24x24のBDFが無い。これらのサイズは、
セルの大きさが合うBDFが手元にあれば`--k24`などで指定する。無ければ空白になる。

### そのほかのBDF

セルの大きさが指定するサイズに合い、ENCODINGがJIS区点コード（漢字）またはASCII/JIS X 0201
（半角）であるBDFなら使える。フォントのライセンスは各自で確認すること。

## 仕組み（概要）

CGROM内には英数字(ANK)4種・漢字(全角)2種、計6種類のフォントサイズがある。

| サイズ | 対象 | 文字数 | オフセット | 1文字あたり |
|--------|------|--------|-----------|------------|
| 16x16 | 漢字(非漢字752+第一水準3008+第二水準3478) | 7238 | `$000000`〜 | 32B |
| 8x8 | 半角(ANK) | 256 | `$03A000` | 8B |
| 8x16 | 半角(ANK) | 256 | `$03A800` | 16B |
| 12x12 | 半角(ANK) | 256 | `$03B800` | 24B |
| 12x24 | 半角(ANK) | 256 | `$03D000` | 48B |
| 24x24 | 漢字(同上) | 7238 | `$040000`〜 | 72B |

1ラインは、左端を最上位ビットにして詰め、バイト境界まで0でパディングする
（12ドット幅の下位4bitが常に0になるのはこの規則による）。BDFの各グリフは、
`BBX`のオフセットに従ってセル（`FONTBOUNDINGBOX`）内に置き直してから詰める。

## 制限・既知の課題

- BDF以外のフォント（TTF/OTF/PCFなど）は読めない。
- 見た目は元のBDFの字面そのもの。実機ROMの字面とは一致しない。
- 東雲フォントだけでは、16x16漢字と8x16半角しか作れない（上記）。
