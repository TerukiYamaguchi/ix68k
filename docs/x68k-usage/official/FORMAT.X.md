# FORMAT.X

> ディスクのフォーマット（初期化）。2HDディスクのFAT初期化や、スイッチ指定による高速フォーマットに対応

---

## リファレンス（一次資料要約）

### 起動・コマンドラインオプション

書式（コマンドライン実行時）:

```
FORMAT ［＜d:＞］ ［/S］ ［/C］ ［/V ＜ラベル＞］
```

**対話型（パラメータなし）:**

`FORMAT` のみで実行すると、フロッピーディスク／SCSI装置の選択→ドライブ指定→ボリューム名設定→実行のメニュー画面が開きます。

**コマンドラインフォーマット（フロッピーディスクのみ対応）:**

指定ドライブをフォーマットします。スイッチの組み合わせで物理フォーマット、システム転送、ラベル指定をコントロール。

| スイッチ | 説明 | 備考 |
|---------|------|------|
| `/S` | フォーマット後、現在のドライブからシステムファイル（HUMAN.SYS, COMMAND.X）を転送 | 最後にラベル入力を促す |
| `/C` | 物理フォーマット済みディスクの管理領域（FAT部＋ディレクトリ部）のみを初期化。高速 | 物理フォーマット済みディスクのみ対応 |
| `/V` | ボリュームラベル指定時に使用。半角21文字以内 | 省略時は "Human68k" がデフォルト |

## ix68kでの利用

### MCP アクション

```
run_command("FORMAT B:")
run_command("FORMAT B: /S /V MYFLOPPY")
```

### 検証メモ

- 検証: `FORMAT B:` 実行 → 初期化完了 → `DIR B:` で空ディレクトリ → `ECHO ... > B:TEST.TXT` /
  `TYPE B:TEST.TXT` でファイル読み書きも正常（2026-07-10、`_B_FORMAT`対応後にMCPで確認）
- 補記: `_B_FORMAT`(0x4D) は標準2HDも含め実機ROM(`$FF90AA`)へ委譲し、ROMが発行する
  FDC の FORMAT TRACK(0x0D、`fdc_format_complete()`)がXDFイメージへフィルします。
  それ以前は標準2HDのみ `x68k_bus_fdc_format_track()` によるホスト直接フィルだった

### SCSI HDD対話メニュー（2026-08-14 ix68k検証）

使い捨てテスト用HDD（`hu68disk mkfs --type scsi --size 50`で作成、`disk/SYSTEM_HD.HDS`本番には
未使用）で`FORMAT`引数なし起動→「SCSI装置」→ID0選択、の対話メニューをMCP経由で検証。

- **「装置初期化」（物理フォーマット）: ❌ 動作しない**。実行すると
  `物理フォーマット出来ませんでした`エラーで失敗します。マニュアル記載の手順通りには進めません。
- **「領域確保」（パーティション作成＋システム転送）: ✅ 動作する**。ただし前提として、対象装置に
  `hu68disk mkfs`等で有効なパーティション構造が既にあること（装置初期化を経ずに直接「領域確保」
  →容量入力→「システム転送：する」→実行、で成功しました。空き容量0の状態でも先に「領域解放」して
  空き容量を作れば再度「領域確保」できる）。
- **「システム転送：する」の効果を確認**: 実行後`DIR`すると`COMMAND.X`が見える（かつ隠し属性の
  `HUMAN.SYS`も書き込まれる、使用容量の増分から確認）。つまり**HUMAN.SYSとCOMMAND.X両方**を
  一度に書き込みます。`SYS.X`（HUMAN.SYSのみ転送、下記`SYS.X.md`参照）とは範囲が異なります。
- 「終了」選択後の`ハードディスクの使用には再起動が必要です リセットしますか？`もマニュアル通り。
  `Y`でリセットすると即座に反映され、`SWITCH B=SCSI0`と組み合わせて実際にこのHDDから
  Human68kが起動することも確認済み（`SWITCH.X.md`参照）。
- **結論**: 実機マニュアル通りの「装置初期化→領域確保」という完全な対話フローは、ix68kでは「装置初期化」の時点で止まる。ただし`hu68disk mkfs`で低レベル構造を
  作った装置に対する「領域確保（システム転送込み）」単体は実機同等に動作します。
