# DRIVE.X

> ドライブの種類と状態を表示し、ドライブ名を交換します。

---

## リファレンス（一次資料要約）

### 起動・コマンドラインオプション

書式:

```
DRIVE [/V] [/D] [<d1:>] [<d2:>]
```

引数の与え方で動作が変わる:
- 引数なし: 全ドライブの種類を一覧表示
- `<d1:>` のみ: 指定ドライブの詳細状態を表示
- `<d1:>` と `<d2:>` の両方: 2つのドライブ名を入れ替える（カレントドライブもそれに追従する）

| オプション | 効果 |
|-----------|------|
| `/V` | ボリュームラベルも併せて表示する（ハードディスクを複数領域に分けている場合のラベル確認向け） |
| `/D` | 全ドライブ名を初期状態に戻す（`<d1:>`・`<d2:>`とは同時指定できない） |

---

## ix68kでの利用

### MCP アクション

```
run_command("DRIVE")
run_command("DRIVE A:")
run_command("DRIVE A: D:")
```

### 検証メモ

- **検証: ix68k確認済み（2026-08-14）**。以下いずれもMCP経由で確認:
  - `DRIVE`（引数なし）: 全ドライブの種類・ユニット番号一覧を表示（A:2HD/B:2HD/C:ハードディスク(SCSI)等）
  - `DRIVE A:`: 指定ドライブの詳細（1セクタバイト数・クラスタ数・ルートディレクトリ先頭セクタ等）を表示
  - `DRIVE A: C:`: ドライブ名交換が成功。メッセージ`ドライブ A:とドライブ C:を入れ替えました`
    `カレント A:をドライブ C:に切り替えました`が出て、プロンプトも`A>`→`C>`に追従した
    （マニュアル記載の「交換後カレントドライブも追従する」を確認）
  - **重要な注意点（ix68kで発見）**: ドライブ名交換は**PATH環境変数を自動更新しない**。
    交換直後に`SET`で確認すると`path=A:\;A:\BIN;...`のようにスワップ前のドライブ文字が
    そのまま残っており、スワップ後の`A:`が別の物理装置を指すようになった結果、
    交換後に`DRIVE`等の外部コマンドが`コマンドまたはファイル名が違います`で
    見つからなくなる事故を実際に再現した（フルパス指定`C:\BIN\DRIVE A: C:`で復旧可能）。
    ドライブ入れ替えをAUTOEXEC.BAT等に組み込む場合は、PATH文字列も別途書き換えるか、
    スワップをPATH設定より前に置く必要があります。
  - `/D`（全ドライブ初期状態リセット）は今回未検証（上記PATH破損からの復旧を優先したため）
