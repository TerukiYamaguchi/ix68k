# MAKE.X

> ファイル間の依存関係を宣言しておくと、更新が必要な部分だけを選んでコンパイル・
> アセンブル・リンクを自動実行してくれるビルドツール。

---

## リファレンス（一次資料要約）

### 概要

複数ファイルからなるプロジェクトを毎回フルビルドする代わりに、MAKEはターゲット（生成物）と
その依存ファイルの**タイムスタンプ**を見比べ、依存ファイルの方が新しいターゲットだけを選んで
再生成します。ソースが1本しかない小規模プロジェクトでも、後から拡張することを見越してメイクファイルを
用意しておくことが勧められています。

### 起動・コマンドラインオプション

書式:

```
MAKE [<スイッチ>] [<マクロ定義>] [<最終ターゲット>]...
```

例: `MAKE /s /n VPATH=SOURCE TEST.X`

コマンドラインの各語は、`/`または`-`で始まれば「スイッチ」、`名前=値`の形なら「マクロ定義」、
それ以外は「ターゲット名」として解釈される（空白を含む語は`"`で囲む）。スイッチは記述順に
左から処理されます。

読み込むメイクファイルは`/f`で指定しなければ`makefile`固定。最終ターゲットを省略した場合は、
メイクファイル中で最初に現れる規則（暗黙規則を除く）の最初のターゲットが自動的に選ばれる
（`!`で始まるターゲットや`include`/`MAKEFILES`経由で読み込まれたファイル中のターゲットは
この自動選択の対象外）。

スイッチは大きく「実行そのものを変えるもの」「情報表示のみで実行はしないもの」の2系統に
分かれます。

実行内容を変えるスイッチ:

| スイッチ | 効果 |
|---------|------|
| `/a` | タイムスタンプの新旧を無視し、依存関係を持つ全ターゲットを強制的に再生成する |
| `/c <path>` | 実行前にカレントディレクトリを指定パスへ切り替える |
| `/e` | メイクファイル中のマクロ定義より環境変数を優先させる（環境ごとに挙動が変わりうるため非推奨） |
| `/f <file>` | 読み込むメイクファイルを指定する（`-`指定で標準入力から読む） |
| `/i` | コマンドの終了コードによるエラー中断を無視する（互換性のためだけに残る、非推奨） |
| `/I <path>` | `include`指令でファイルを探すディレクトリを追加する |
| `/k` | あるターゲットの処理がエラーで止まっても、他のターゲットの処理は続行する |
| `/S` | 直前に指定した`/k`を打ち消す |
| `/o <name>` | 指定ターゲットを「一番古いファイル」扱いにする（自身は更新されず、これに依存する他ターゲットへも影響しない） |
| `/R <name>` | 指定ターゲットを「存在しないもの」扱いにし、必ず更新対象にする |
| `/s` | 実行するコマンド行を画面に出さない（`/n`指定時はこの抑制自体が無視される） |
| `/t` | 実際にはコマンドを実行せず、ファイルの更新日付だけを今の時刻に変える |
| `/w` | 各コマンド実行の前後でカレントディレクトリを表示する |

情報表示・ドライラン用のスイッチ（実際の生成は行わない、または補助情報を出すだけ）:

| スイッチ | 効果 |
|---------|------|
| `/d` | メイクファイル・環境変数・ディレクトリ内容などのデバッグ情報を表示する |
| `/D` | 内部で構築したファイル依存関係データベースを標準出力へ出す |
| `/h` | コマンド書式と全スイッチの説明を表示して終了する |
| `/n` | コマンドは実行せず、実行されるはずのコマンド行だけを表示する（ただし`$(MAKE)`を含む行は`/n`指定時も実際に実行される） |
| `/N` | `/p`と組み合わせて使う、考査（依存関係の評価）自体を行わないモード |
| `/p` | メイクファイル・環境変数・コマンドラインから組み立てた内部データベースを表示する |
| `/q` | 実行はせず、更新が必要なターゲットがあれば終了コード1、なければ0を返す（他コマンドからの呼び出し用） |
| `/v` | バージョン情報を表示する |
| `/W <name>` | 指定ターゲットを「最新のファイル」扱いにする（自身は更新対象から外れるが、これに依存する他ターゲットは更新されうる） |

### メイクファイルの書式

規則1つの基本形は「ターゲット行」＋「TAB始まりのコマンド行」。コマンド行の先頭のTABは省略できません。

```
<ターゲット名>: <依存ファイル名>...
<TAB><コマンド>
```

ターゲットを引数なしで`MAKE`だけ実行したときに選ばれるのは、メイクファイル中で一番最初に
書かれた規則なので、最終的なゴール（実行ファイルなど）を**ファイルの先頭**に置くのが定石。

```makefile
# ゴール: リンクして実行ファイルを作る
myapp.x: myapp.o util.o
	lk myapp.o util.o

# 依存ファイル自身も、別の規則ではターゲットになれる
myapp.o: myapp.c
	cc /Fc myapp.c

util.o: util.s
	as util.s
```

メイクファイルの各行は次の5種類のいずれかに分類されます。

| 行の種類 | 中身 |
|---------|------|
| 空行 | 無視される |
| コメント行 | `#`から行末まで（行頭でも文中でもよい。行末の`\`で次行へ継続） |
| マクロ定義行 | `<名前> = <値>` または `<名前> := <値>` |
| 規則行 | `<ターゲット名> [<パターン>:] <依存ファイル>...`、続くTAB始まりの行がコマンド |
| 指令行 | `if`/`include`/`define`/`override`/`undef`/`vpath`/`error`など。キーワードは小文字固定 |

規則の書き方には4通りあります。用途が狭いものから広いものへ:

1. **通常の規則** — ターゲットと依存ファイルを1対1で直接書く（上の例がこれ）
2. **明示的なパターン規則** — `%`を使い、ターゲット・パターン・依存の対応関係を自分で書く
3. **暗黙のパターン規則** — コマンドを書かない規則があると、MAKEが`%`から自動的に対応するファイルを推測する（対象がphonyターゲットや終端ターゲットでない場合）
4. **暗黙の接尾辞規則** — `.SUFFIXES`と`.c.o:`のような旧来の書き方。内部的には3の暗黙パターン規則へ自動変換される（過去のメイクファイルとの互換性のために残っている）

```makefile
# 2: 明示的なパターン規則の例
$(PROG): %.x: %.o $(AOBJ)
	$(LC) $(LFLAGS) $< $(AOBJS)

%.o: %.c $(CINC)
	$(CC) $(CFLAGS) $<

%.o: %.s $(AINC)
	$(AS) $(AFLAGS) $<
```

```makefile
# 4: 接尾辞規則の書き方（実体は上の2/3と同じ扱いになる）
.SUFFIXES: .x .o .s .c
.c.o:
	$(CC) $(CFLAGS) $<
```

ドット始まりの名前はターゲットとしてではなく「特殊ターゲット」として扱われ、MAKE自体の
挙動を変える:

| 特殊ターゲット | 効果 |
|--------------|------|
| `.SUFFIXES` | 接尾辞規則が対象とする拡張子の一覧を宣言する |
| `.DEFAULT` | どの規則にも一致しないターゲットに使う既定のコマンドを定義する |
| `.IGNORE` | `/i`スイッチと同じ効果をメイクファイル内から指定する |
| `.PHONY` | 実ファイルに対応しない、常に実行させたいターゲットを宣言する |
| `.PRECIOUS` | 暗黙規則で生成した中間ファイルを自動削除しないようにする |
| `.SILENT` | `/s`スイッチと同じ効果をメイクファイル内から指定する |
| `.TERMINAL` | このMAKE独自の拡張。指定したターゲットを終端扱いにし、暗黙規則の適用対象から外す |

### マクロ

繰り返し使う文字列（コンパイラ名・フラグ・ファイル名など）はマクロにまとめて使い回せます。

```makefile
CC = cc
CFLAGS = /O /L
PROG = myapp.x
SRC = $(PROG:.x=.c)     # 末尾を置換: myapp.x → myapp.c
OBJ = $(SRC:.c=.o)      # myapp.c → myapp.o

$(OBJ): $(SRC) $(CINC)
	$(CC) $(CFLAGS) $<
```

参照時は1文字マクロなら`$M`、複数文字なら`$(MACRO)`または`${MACRO}`と書きます。マクロの中で
別のマクロを参照する入れ子（`$($(MACRO))`）も書けます。未定義のマクロは空文字列として扱われます。

同じマクロが複数箇所で定義された場合、どの定義が実際に使われるかは次の優先順位で決まる
（数字が大きいほど強い）:

1. MAKE自身が持つデフォルトマクロ
2. 環境変数（`/e`を指定していない場合）
3. メイクファイル中の通常の定義
4. 環境変数（`/e`を指定した場合）
5. コマンドラインで渡した定義
6. `override`指令による定義
7. 自動マクロ（後述）

MAKEがターゲットを処理する際に自動で設定するマクロ:

| マクロ | 中身 |
|-------|------|
| `$@` | いま更新しているターゲットのファイル名 |
| `$<` | そのターゲットが依存する最初のファイル名 |
| `$*` | パターン規則で`%`にマッチした部分（ステム） |
| `$^` | ターゲットより新しい依存ファイルの一覧 |
| `$+` | そのターゲットが依存する全ファイルの一覧 |

`$@`・`$<`・`$*`はさらに`D`（ディレクトリ部分のみ）・`F`（ファイル名部分のみ）を付けて
`$(@D)`・`$(@F)`のように絞り込めます。

このほか、`MAKE`自身のパス名を持つ`MAKE`マクロ、ネストの深さを表す`MAKELEVEL`、事前
読み込みファイルの一覧`MAKEFILES`、検索パスの一覧`VPATH`、上書き用の`MAKEOVERRIDES`
といった特殊マクロが用意されています。

マクロ展開時に呼べる関数群（キーワードは小文字固定）:

| 呼び出し | 働き |
|---------|------|
| `$(origin <マクロ名>)` | そのマクロがどのレベル（上記1〜7）で定義されたかを数値で返す（0は未定義） |
| `$(foreach <仮マクロ>, <リスト>, <文字列>)` | リストの要素を1つずつ仮マクロに割り当てながら文字列を展開し、空白区切りで連結する |
| `$(join <文字列1> [<文字列2>])` | 2つの文字列を空白で連結する |
| `$(wildcard <リスト>)` | Human68kのワイルドカード規則でファイル名を展開する |
| `$(calculate <式>)` | 式を計算した結果を展開する |

さらに`$(マクロ|フィルタ)`という書き方で、マクロの中身を加工するフィルタを通せる
（フィルタ名も小文字固定、対応するスイッチがある場合は`filter-switch`の形で付ける）。
使えるフィルタは `addprefix` / `addsuffix` / `basename` / `dir` /
`extract <パターン>`（`i`=大小無視、`v`=不一致抽出）/ `findstring` / `head` /
`sort`（`i`=大小無視、`r`=逆順）/ `strip` / `subst <検索>=<置換>`（`i`=大小無視、
`s`=語末のみ、`p`=パターン検索）/ `suffix` / `tail` / `tolower` / `toupper` /
`uniq`（`f`=大小無視、`d`=非連続の重複も除去）/ `word <n|n-|-n|n-m>` / `words`。

### 指令

指令行のキーワードはすべて小文字で書く必要があります。

```
if <式> ~ elif <式> ~ else ~ endif
include <パス名>
define <マクロ名> ~ endef
override <マクロ名> = <値>  /  override <マクロ名> := <値>
override define <マクロ名> ~ endef
undef <マクロ名リスト>
vpath [<パターン> [<パスリスト>]]
error [<メッセージ>]
```

- `if`〜`elif`〜`else`〜`endif`: `elif`は何個でも書け、入れ子にもできます。条件式の中のマクロは
  評価前に展開されます。使える演算子は、数値比較・算術用の
  `+ - * / % & ^ | && || << >> < > <= >= == !=`、文字列比較の`== != =~ !~`
  （`=~`と`!~`はパターンマッチ）、ファイルの状態を調べる`=a =d =e =f =h =s =w =z`
  （順にアーカイブ・ディレクトリ・存在・通常ファイル・隠し属性・システム属性・書込可能・
  サイズ0を意味する）
- `include`: 指定したファイルをその場に読み込みます。相対パスで見つからなければ、`/I`で
  追加した検索パスを順に試す
- `define`〜`endef`: 複数行にまたがる文字列を、優先順位3（メイクファイル中の定義相当）の
  マクロとして定義する
- `override`: 優先順位6（コマンドラインでの定義より強い）でマクロを定義する
- `undef`: マクロ定義を削除する（英数字または`_`で始まらない名前、もともと未定義の名前は
  対象外）
- `vpath`: 指定パターンに合うファイルを探す検索パスを`;`区切りで指定する
- `error`: メッセージを表示してMAKEの実行を打ち切る

### メイクファイルの例（複数ソースをまとめてライブラリ化する）

暗黙のパターン規則を使うと、ソースファイルを1つずつ列挙しなくても、依存関係の側から
必要なコンパイルが自動的に導かれます。

```makefile
CC = cc
CFLAGS = /O /Fc
AS = as
AFLAGS =

MODULES = mod1.o mod2.o mod3.o mod4.o mod5.o

utillib.l: $(MODULES)
	lib /u utillib.l $(MODULES)

%.o: %.c
	$(CC) $(CFLAGS) $<

%.o: %.s
	$(AS) $(AFLAGS) $<
```

`mod1.c`〜`mod5.c`（または`.s`）を個別の規則として書く必要はありません。`utillib.l`が
`$(MODULES)`（`mod1.o`〜`mod5.o`）に依存していると宣言するだけで、各`.o`をどう作るかは
下の暗黙パターン規則がファイル名から自動的に判断します。
