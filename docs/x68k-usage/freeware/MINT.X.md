# MINT.X (mint)

> TF/STFの流れをくむ2画面ファイラ。簡易言語（madoka）搭載、プラグインでファイル表示をカスタマイズ可能。GPLv2。Human68k v3.02以降必須。

---

## リファレンス（一次資料要約）

### 起動

```
MINT
```

### 基本操作

mintはTF/STF系の**2画面（ツインウィンドウ）ファイラ**。キー割り当てはすべて定義ファイル
（`_mint`、環境変数`MINTRC3`で指定）側で決まる仕組みで、**`\BIN`に導入済みの`_mint`は
メンテナ本人（TcbnErik）が自分用にカスタマイズしたサンプル**であり、README.mdでも
自由に書き換えることが前提とされています。以下はそのサンプルから読み取れる、汎用的な
ファイル操作に対応するキーのみを抜粋したもの（GCC/HAS等の開発ツールや音源ドライバに
対応するキーは配布者個人の環境に依存するため割愛）。

カーソル・ウィンドウ移動:

| キー | 動作 |
|------|------|
| ↑ / ↓ / ← / → | カーソル移動（左右端まで来ると反対側ウィンドウへ移る設定になっている） |
| Roll Up / Roll Down | ページ単位の送り（先頭/末尾では逆側の末尾/先頭へ回り込む） |
| TAB | 反対側ウィンドウへカーソルを移す |
| HOME/CLR | カレントドライブのルートディレクトリへ移動 |
| . (ピリオド) | 1つ上の階層へ移動 |
| UNDO | 1つ上の階層へ移動（ピリオドと同じ割り当て） |
| \ | ルートディレクトリへ移動（アーカイブ内なら1階層ずつ抜ける） |
| J | 登録済みパスの一覧から移動先を選ぶ |
| H | 移動履歴の一覧を開く |
| O | 反対側ウィンドウと同じパスへ移動する（既に同じなら反対側のパスへカーソルごと移動） |

ファイルの選択・実行:

| キー | 動作 |
|------|------|
| RETURN | カーソル位置を実行、ディレクトリなら中へ入る |
| SPACE | カーソル位置をマーク |
| BS (DELの左隣) | マークを外す |
| A | 全ファイルのマーク状態を反転させる |
| HELP | 次に押すキーの割り当て内容を画面に表示する（動作を調べたいときに使う） |
| F, / | ファイル名の一部を入力して絞り込む |

ファイル操作:

| キー | 動作 |
|------|------|
| C | 反対側ウィンドウへコピー |
| M | ディレクトリを作成してその中へ移動する |
| K | ディレクトリを作成する（移動はしない） |
| R | 名前を変更する |
| DEL | 削除する（削除不可属性のファイルは設定に応じて確認が入る） |
| T | タイムスタンプを変更する |
| W | ファイルを比較する |
| L | ファイルの中身を表示する（テキストビューア） |
| N | ファイル名でソートする |
| S | 拡張子・時間・サイズ等でソートする（既定の並び順は設定に従う） |
| Y | マーク中のファイル名を一覧表示する |

ドライブ・システム:

| キー | 動作 |
|------|------|
| D | ドライブ変更メニューを開く |
| 英字キー + XF5 | そのドライブレターへ直接切り替える（例: XF5+C → C:） |
| Q | 終了する（終了時に保存先パスを選ぶメニューが出る） |
| X | 登録済みコマンドの一覧から実行する |

定義ファイル（`_mint`）の編集: mintを終了せずにその場で`_mint`本体を編集できます。保存して
エディタを終了すると自動的に再読み込みされ、再起動なしで新しい定義が反映されます。

| キー | 動作 |
|------|------|
| SHIFT+F | 環境変数`$EDITOR`で`_mint`を開きます。保存終了で設定が即座に反映される |
| CTRL+F | 同上に加えて、対応するマニュアルページも一緒に開く（エディタが対応していれば分割表示） |

`$EDITOR`が未設定だと動きません。起動時に`em`/`supered`/`edr`/`ed`の順で使えるものを
自動検出して設定する仕組みになっている（いずれも導入されていないと空のままになる）。

キー定義の記法について: `_mint`定義ファイル中の各キー行は、`-`に続けて記号を並べて
指定を組み合わせる形式になっています。記号は大きく2種類あり、①どのキー入力で発動するかを
決めるもの（無指定時の動作を別のキー組み合わせに置き換える）と、②発動後の実行のされ方
（見た目・挙動）を決めるものが混在します。①だけが省略された行は「無修飾（素押し）のまま」
という意味になります。動作を正確に確認したいときはHELPキーで実際に調べるのが確実。

①入力トリガー（無修飾のキーをどれに置き換えるか）:

```
-c      CTRL
-t      SHIFT
-x<n>   XF<n>
-o<n>   OPT.<n>
-&<n>   &prefix <n>（プリフィックスモードの2打鍵目）
-m      マークがあるときのみ
-!      誤操作防止の確認を挟む
-j      J特殊エントリ実行時
```

（XF1〜XF5・OPT.1/OPT.2はX68000キーボードのファンクションキー列右側にある拡張キー）

②実行スタイル（キー組み合わせに関わらず追加で付けられる指定）:

```
-k      キー入力待ち(表示あり)          -a   コマンドヒストリに残さない
-h      キー入力待ち(表示なし)          -d   ディレクトリ再読み込み
-f      ファンクションキー表示を消す    -n   実行しない
-i      カーソルを消す                  -v   シェルを起動しない
-l      実行後コンソールを消す          -g0  &gvram-off
-s      全画面で実行                    -g1  &half( 16色)   -g5 &gvon( 16色)
-p      コマンドラインを表示しない      -g2  &half(256色)   -g6 &gvon(256色)
-q      透明プライオリティを復帰        -g3  &half(自動)    -g7 &gvon(自動)
-@      テキストパレットを復帰          -g4  &half(64K色)   -g8 &gvon(64K色)
                                        -g9  &gvon( 16色、24kHz)
```

例えば`_mint`定義中のSHIFT+F（`-tapi`）の`api`部分は「コマンドヒストリに残さず・
コマンドラインも表示せず・カーソルも消して実行する」という組み合わせで、エディタ起動を
静かに済ませるための指定であり、キー割り当て自体（①）には関与しません。

## ix68kでの利用

### 入手先

- **v3.10**（retropc.net配布、原作: Thule./ippoh/Leaza/AKT各氏、作者: 立花えり子氏）:
  http://retropc.net/x68000/software/tools/filer/mint/ から`MINT310.ZIP`（734.0KB）を
  ダウンロード可能。**`arc/MINT310.ZIP`にローカル保存済み**（2026-07-30取得）。
  ページはShift_JIS・httpのみ（httpsは証明書の検証に失敗するため、
  `http://`のURLで取得する）。
- **v4.4.3**（GitHub kg68k/mint、現行メンテナTcbnErik氏）:
  https://github.com/kg68k/mint の Releases ページから最新版のzip（例: `mint443.zip`）を
  ダウンロード可能（ビルド済みバイナリ`mint.x`同梱、ソースは別途`src/`）。
  **`arc/mint443.zip`にローカル保存済み**（2026-08-04取得）。
- 再検証・再インストール時は上記URLへ再度アクセスせず、まずローカル保存済みzipを使うこと。

`README.md`（アップデート方法）に明記の通り、**mint version 3 以降からのアップデートは
定義ファイル（`_mint`）以外を上書きするだけでよい**。v3.10からv4.4.3への上書き・
v4.4.3からv3.10への上書き（意図的なダウングレード）の両方向を本手順で確認済み。

### インストール（SYSTEM_HD.HDSへの導入手順）

```sh
# 1. ダウンロード（arc/mint443.zipにローカル保存済みならそれを使い、再ダウンロードしない）
cp arc/mint443.zip ./mint443.zip
# 無ければ: curl -LO https://github.com/kg68k/mint/releases/download/v4.4.3/mint443.zip
# (他バージョンは `gh release list --repo kg68k/mint` で確認)

# 2. 展開（unar、要 brew install unar）
unar -o ./mint_extracted mint443.zip
# → ./mint_extracted/mint443/{mint.x, _mint, docs/, madoka/, plugin/, emacs/, ...}

# 3. mint.xと定義ファイル_mintをHDSの\BINへコピー（hu68disk、エミュレータ停止中に実行）
tools-host/hu68disk/hu68disk copy disk/SYSTEM_HD.HDS ./mint_extracted/mint443/mint.x /BIN
tools-host/hu68disk/hu68disk copy disk/SYSTEM_HD.HDS ./mint_extracted/mint443/_mint /BIN
```

**重要（`\BIN`に置くだけでは起動しない）**: `_mint`は環境変数`MINTRC3`（またはv2互換の
`MINTRC`、あるいは`HOME`下に`.mint`という名前で配置）でパスを明示しないとmint.xが
見つけられず、`定義ファイル名をパス名から環境変数MINTRCに指定するか、環境変数HOME下に
.mintとして定義ファイルを置いて起動して下さい。`とエラー終了する（同梱`MINT_V3.1ST`にも
明記）。**`AUTOEXEC.BAT`に`SET MINTRC3=C:\BIN\_mint`を追記済み**（2026-07-30、
`PATH`設定行の直後）。起動時に自動設定されることを`SET`コマンドの出力で確認済み。

### MCP アクション

```
run_command("MINT")   # MINTRC3はAUTOEXEC.BATで設定済みのため個別設定は不要
```

### 検証メモ

- 検証: 2026-07-30、SYSTEM_HD.HDS(`\BIN\MINT.X`+`\BIN\_mint`)からix68k起動して確認。
  - `\BIN`に両ファイルを置いただけの状態で`MINT`を実行 → 設定ファイル未検出エラーで
    即終了（クラッシュではない、正常なエラーメッセージ）。**ユーザー指示通り「\BINへ
    コピーするだけ」では起動できない**ことを確認。
  - `SET MINTRC3=C:\BIN\_mint`（`AUTOEXEC.BAT`に追記済み）で設定ファイルは検出されます。
  - 当初`MINT`実行時にバスエラー（`SR=$0011:PC=$0007C6DE`）が発生していたが、これは
    **ix68k側の不具合**と判明・修正済み。
    `ea_rmw_read()`が`BTST D0,#imm`（即値ソースの動的ビットテスト、mint.xの`_mint`
    パーサ内で使用）を誤って例外扱いにしていたバグで、実際のバスエラーは一切
    発生していなかった（誤診断）。修正後、`MINT`は正常起動し2画面ファイラUIが
    表示されることを確認済み。
- **結論: インストール・起動とも正常動作を確認済み。**

#### 既知の不具合: `temp`未設定時、`.LZH`にRETURNでアドレスエラー

- 症状: `.LZH`/`.LHA`ファイルにカーソルを合わせ無修飾RETURN（内蔵`&lzh-selector`、
  `_mint`定義1019-1026行目）を押すと、環境変数`MINTTMP`／`temp`／`TEMP`のいずれも
  未設定の場合、CPUアドレスエラーで異常終了します。SCSI・FDどちらのドライブでも再現
  （ドライブ種別非依存）。v3.10でも同様に再現すると見られる（バージョン非依存の
  mint.x本体側バグ）
- 原因: `extern/mint/src/mintarc.s`の構造体`mintarc_buffer`で`MA_TMP_DIR`フィールドが
  奇数オフセット(105)に配置されており（`.even`ディレクティブ欠落）、`temp`未設定時に
  呼ばれる`get_curdir_a1`（`fileop.s:150-151`、偶数アドレス必須と明記）にそのまま
  渡され、`MOVE.L`で奇数アドレス書き込み→アドレスエラーとなります。エミュレータ側の
  バグではなく、MC68000の仕様通りの正しい動作
- 対処: `AUTOEXEC.BAT`に`SET temp=C:\TMP`を追記し、`C:\TMP`ディレクトリを作成済み
  （2026-08-13、`disk/SYSTEM_HD.HDS`に適用済み）。以後この経路には入らず回避できる
- 参考: `_mint`定義ファイル（686行目）の`&setenv MINT_TMP $<`はキー名が`MINT_TMP`だが、
  mint.xが実際に読む環境変数は`MINTTMP`（アンダースコアなし）／`temp`／`TEMP`
  （`mint.s:879-881`）。このキーバインドで設定しても効かない（上流側の不整合の可能性）
