# GED.X (GhostED)

> MCPサーバからHuman68k上のテキストファイルを直接編集するための自作ed風ラインエディタ。

---

## リファレンス（コマンド仕様）

書式:

```
GED <ファイル名>
```

存在しないファイルを指定すると新規作成扱い（空バッファ）になります。起動後は`: `
プロンプトに対し1行でコマンドを入力します。

| コマンド | 動作 |
|---|---|
| `l` | 現在位置でビューポート再描画（移動なし） |
| `g <n>` | n行目へ移動 |
| `i` | カレント行の**前**に挿入モード開始。単独の`.`行で終了 |
| `a` | カレント行の**後**に挿入モード開始（同上） |
| `d` | カレント行を削除 |
| `d <n1> <n2>` | n1〜n2行を削除 |
| `w [name]` | 保存（省略時は開いているファイル名） |
| `q` | 終了（未保存の変更があれば拒否） |
| `q!` | 変更を破棄して終了 |
| `?` | コマンド一覧をビューポート領域へ表示（`l`で元の表示に戻る） |

画面はビューポート（行番号ガター＋本文、行末は`$`）とモードライン（ファイル名・
変更フラグ`*`/`=`・位置割合、水色帯）から成る。画面レイアウトの詳細・実装方針は
`tools-x68k/ged/DESIGN.TXT`（Shift-JIS）を参照。

## ix68kでの利用

### ビルド

`C:\BIN\GED.X`として実際に導入しているのは**X68000上のネイティブGCC
（`freeware/GCC.X`）でビルドした版**（`tools-x68k/ged/native/GHOSTED.C`）。
一般的な移植手順（DOSCALLヘッダ差し替え・UTF-8→CP932変換）は
`docs/x68k-usage/development/native_build.md`参照。ビルドコマンド:

```
GCC -O GHOSTED.C -lgcc -ldos -o GED.X
```

Mac上での通常のクロスビルド（`elf2x68k`）も引き続き可能（開発時の主経路）:

```sh
cd tools-x68k/ged
make            # m68k-xelf-gcc → elf2x68k.py → GED.X
```

（2026-08-27時点、両ビルドはコード上は同一だがバイナリサイズが異なる
——ネイティブ版27,248バイト・クロス版約99KB——ため区別できます。）

### インストール（HDSへの配置）

クロスビルド版をhu68disk経由で配置する場合:

```sh
tools-host/hu68disk/hu68disk copy <対象HDS> tools-x68k/ged/GED.X BIN/GED.X
```

稼働中のHDSへ直接書き込んだ場合、Human68k側のFATキャッシュには反映されないため
`reset()`が必要（`disk`ツールの仕様と同様）。**HOSTDRV経由（`F:\WORK\`等）で配置すれば
リセット不要**で即座に認識される（`ix68k.cfg`の`hostdrv_dir`参照）。ネイティブ版は
X68000上でビルドしたその場で`COPY <出力名>.X C:\BIN\GED.X`すればよい（reset不要）。

### MCP アクション

```
run_command("GED <ファイル名>")     # 起動（新規/既存どちらも可）
run_command("<コマンド>")           # 以後は1コマンドずつ送る
```

各コマンドの結果は`@GED OK ...`/`@GED ERR ...`の固定書式でステータス行に出ます。
`run_command`の戻り値からこの行を探して結果を判定する（プロトコル詳細は設計書
「MCP連携プロトコル」参照）。目視確認は`screenshot()`または`read_bitmap_text()`。

### 検証メモ

- 検証: 2026-08-27、MCP経由（`run_command`）でロード/`l`/`g`/`i`/`a`/`d`/`w`/`q`/`q!`/`?`
  すべてix68k確認済み。
- 行内の制御コード（例: Human68kのEOFマーカー`$1A`）は素通しすると画面消去等の
  誤動作を起こすため、表示時のみ`^X`表記に変換します。保存内容は
  原文のバイト列のまま変更しません。
- 末尾が単独のEOFマーカー`$1A`であるファイルでは、`a`による最終行への追記を
  自動的にその直前へ入れます。`AUTOEXEC.BAT`などを編集する際、AIエージェントの指示で
  EOFマーカーの位置を指定する必要はありません。
