# ネイティブビルドとクロスビルドを切り替える

ホスト上のクロスビルドと X68000 上のネイティブビルドでは、同じ C ソースを利用できます。ただし、
DOSCALL ヘッダとソース文字コードは共通ではありません。この文書では、どちらの環境から切り替える
場合も、ホスト上の UTF-8 ソースを正本として扱います。

## 共通の原則

- ホスト側の UTF-8 ソースを正本にします。ネイティブ用に変換した CP932 ファイルだけを編集しません。
- ネイティブ用のソース名は 8.3 形式・大文字にします。
- 成果物の `.X` は、HOSTDRV を使って相手側へ渡します。稼働中の Human68k に固定 HDS へ直接書き込んだ
  内容は、リセットなしには反映されません。
- DOSCALL を使うソースでは、ビルド環境に応じてヘッダを切り替えます。

| 環境 | DOSCALL ヘッダ |
| --- | --- |
| クロス（elf2x68k） | `#include <x68k/dos.h>` |
| ネイティブ（GCC.X / freeware/LIBC） | `#include <doslib.h>` |

`_dos_open`、`_dos_read`、`_dos_write` などの関数名は共通なので、ヘッダ以外の呼び出し側の
C ソースは変更しません。IOCS コールのネイティブ用ヘッダは未確認です。

## クロスビルドからネイティブビルドへ切り替える

1. ホスト側の UTF-8 ソースで、DOSCALL ヘッダを `#include <doslib.h>` に切り替えます。
2. 日本語コメント・文字列リテラルを含む場合は、CP932 へ変換して 8.3 形式・大文字のファイル名で保存します。

   ```sh
   iconv -f UTF-8 -t CP932 source_utf8.c > SOURCE.C
   ```

   波ダッシュ `〜`（U+301C）は CP932 へ変換できないため、変換前に全角チルダ `～`（U+FF5E）へ
   置き換えます。

3. `SOURCE.C` を HOSTDRV 経由で X68000 から見える作業ディレクトリへ置きます。
4. X68000 上で GCC.X を実行します。

   ```text
   GCC -O SOURCE.C -lgcc -ldos -o OUTPUT.X
   ```

   `printf` を使う場合は `-lgcc`、`_dos_*` を使う場合は `-ldos` が必要です。

5. 動作確認後、ネイティブ側で修正した内容があれば、CP932 の生成ファイルではなくホスト側の UTF-8
   正本へ反映します。

## ネイティブビルドからクロスビルドへ切り替える

1. ネイティブ側で変更した `SOURCE.C` を HOSTDRV でホストへ回収します。
2. CP932 ファイルを UTF-8 へ変換し、ホスト側の正本へ内容を反映します。

   ```sh
   iconv -f CP932 -t UTF-8 SOURCE.C > source_utf8.c
   ```

3. DOSCALL ヘッダを `#include <x68k/dos.h>` に戻します。
4. ホスト上で `m68k-xelf-gcc` と `elf2x68k` による通常のビルドを実行します。生成した `.X` は
   HOSTDRV または HOSTFILE で X68000 へ渡して確認します。

既存のクロスビルド手順は [cross_build.md](cross_build.md)、GCC.X 固有の要件と実例は
[native_build.md](native_build.md) を参照してください。
