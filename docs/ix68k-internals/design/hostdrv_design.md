# HOSTDRV リモートデバイス設計

## 1. 目的と構成

HOSTDRV はホストの指定ディレクトリを、Human68k のリモートデバイスとして公開します。
FAT イメージを合成せず、Human68k のファイル要求をホストのファイルシステム操作へ直接対応付けます。
このため、合成 FAT と Human68k のバッファキャッシュの不整合を持ちません。

| 要素 | ファイル | 責務 |
|---|---|---|
| ゲストドライバ | `tools-x68k/hostdrv/` | `\SYS\HOSTDRV.SYS`。リクエストヘッダを MMIO へ渡す薄いブリッジ |
| ホスト処理 | `src/peripheral/hostdrv_remote.c` | comcod を解釈し、ホストのファイル・ディレクトリ操作を実行 |
| FD 管理 | `hostdrv_remote_fd.c` | FCB アドレスとホスト fd の対応、リセット時の一括クローズ |
| バス配線 | `src/bus/x68k_bus.c` | MMIO とゲストメモリアクセサを提供 |

有効化は `-hostdrv <directory>` 相当のホストディレクトリ設定による。ゲストでは
`CONFIG.SYS` に `DEVICE = \SYS\HOSTDRV.SYS` を置きます。

## 2. MMIO プロトコル

MMIO 窓は `$EA0200-$EA020F` です。

| オフセット | 名称 | 方向 | 内容 |
|---:|---|---|---|
| `+00.w` | MAGIC | RO | 未設定=`$0000`、設定済み=`$4844` (`HD`) |
| `+02.b` | COMMAND | WO | `$02`=EXEC |
| `+03.b` | STATUS | RO | 直前のコマンド結果（0=成功） |
| `+04.l` | REG_A5 | WO | ゲストのリクエストヘッダアドレス |
| `+08.w` | REG_D0 | RO | ドライバへ返すエラーワード |

`HOSTDRV.SYS` は初期化 comcod `$40` だけを自身で処理します。その他はリクエストヘッダの
アドレスを REG_A5 に書き、EXEC を発行します。ホスト側はバス経由でリクエストヘッダと
転送バッファを読み書きするため、GVRAM など RAM 外のアドレスも扱えます。

### 2.1 ix68k 以外・未設定での初期化

ix68k 以外（XEiJ・実機）では `$EA0200-` が未割り当てでバスエラーになります。IPLROM の
`_B_WPEEK` は `move.w (a1)+,d0` だけで保護がないため使えません。`HOSTDRV.SYS` は
初期化時、バスエラーベクタ（`$08`）を一時的に差し替えて MAGIC を読み、結果を次の三つに
分ける（`head.S` の `hostdrv_probe_magic`）。

| MAGIC の読み出し | 動作 |
|---|---|
| `$4844` | 通常どおりドライブを登録する |
| 読めたが `$4844` でない | 「ホストディレクトリが未設定」を表示して組み込まない |
| バスエラー | 「ix68k 以外では組み込めません」を表示して組み込まない |

組み込まない場合は初期化エラー（errh=`$70`・errl=`$0C`、D0.W=`$700C`）を返して拒否し、
`CONFIG.SYS` の処理は続く（ブートが止まらないことを ix68k で確認）。ユニット数 0 の正常終了は
使いません。Human68k が devend 以降へ 65536 個（約 768KB）のドライブ管理ノードを作り、
`DRIVE.X` などドライブリストを辿る処理が 65536 回ドライバを呼んで約 8 秒かかるため。
終端アドレスは通常時と同じ `&_end` を返します。デバイスヘッダは Human68k がチェーンへ繋ぎ済みの
ため、先頭を返して解放するとブートが破綻する（XEiJ 060turbo で確認）。この状態でも
Human68k は初期化以外のコマンドを発行しうるため、ドライバは初期化の成否を記憶し、
未登録の間は MMIO に触れず DOS エラー `-15`（無効なドライブ）を返します。

## 3. ファイル操作

comcod `$41-$58` の主要なファイル要求を、ホストの操作へ対応付けます。

- ディレクトリ：`_CHDIR`、`_MKDIR`、`_RMDIR`、`_FILES`、`_NFILES`
- ファイル：`_CREATE`、`_OPEN`、`_CLOSE`、`_READ`、`_WRITE`、`_SEEK`、`_DELETE`、`_RENAME`
- 属性・日時・容量：`_CHMOD`、`_FILEDATE`、`_DSKFRE`

通常のファイルエラーはリクエストヘッダ `+18` に DOS エラーとして返し、`+3/+4` は
物理デバイスエラーだけに使います。`_WRITE` のサイズ0は無視せず、現在位置での truncate とします。
検索状態と開いた fd は FCB ごとに管理し、リセット時には必ず破棄します。

## 4. パス・文字コード・制約

- ホストルートは設定したディレクトリであり、正規化後もその配下に収まることを検証して
  `..` による脱出を拒否します。
- ゲストのパス区切りは内部表現 `$09` を扱い、ファイル名は Shift-JIS と UTF-8 の間で変換します。
- リモートデバイスでは Human68k 本体が相対 `CD ..` をドライバへ送らず失敗します。
  絶対パスを使います。
- CONFIG.SYS で明示的なドライブレターを指定する他デバイスがある場合は、A: からの
  非連続なドライブレターを作りません。

## 5. 検証

- `hostdrv_remote_test`：comcod、ファイル操作、検索、エラー処理。
- `HOSTDRV.SYS` を `CONFIG.SYS` から読み込み、ドライブ登録、読み書き、サブディレクトリ、
  日本語名を ix68k 上で確認します。
- ホストファイルディスクリプタと検索セッションがリセットで解放されることを確認します。
