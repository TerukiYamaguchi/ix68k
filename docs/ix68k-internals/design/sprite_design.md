# スプライトコントローラ設計

## 1. 目的と対象範囲

ix68k のスプライトコントローラ（`$EB0000–$EBFFFF`）による、PCG、BG0/BG1、
スプライトの合成仕様を定めます。

- 対象: MMIO バッキング、PCG/BG/スプライトの描画、SP/BG 内部優先順位、表示モード判定。
- 対象外: CRTC の表示タイミング、ビデオコントローラ R1/R2 による他レイヤとの合成、
  ラスタ単位のタイミング精度。
- レジスタ単位の実装状況は [`sprite_support.md`](../support/sprite_support.md) を正本とします。

## 2. 実装状態

| 項目 | 状態 | 補足 |
| --- | --- | --- |
| 64 KiB MMIO バッキング | ✅ | `$EB0000–$EBFFFF` を `sp_ram` として保持 |
| PCG、BG0/BG1、128 スプライト | ✅ | 透過・反転・スクロール・優先順位を含む |
| 同一走査線 32 個制限 | ✅ | 番号順で先頭 32 個だけ表示 |
| `$EB0810` によるモード判定 | ✅ | CRTC R20 は参照しない |
| `$EB080A–$EB080E` の表示窓調整 | 🔄 | 値は保持するが描画へ未反映 |
| 実機のレジスタ更新タイミング | ❌ | 垂直帰線期間限定などは未再現 |
| CRTC 解像度との出力整合 | ✅ | 描画元の有効解像度を使い、固定ホスト幅へ依存しない |

## 3. 設計の要点

1. SP/BG の表示可否と形状はスプライトコントローラ自身の `$EB0810` と
   `$EB0808` から決めます。CRTC R20 は、直接書き換えるソフトで値が一致しないため
   ゲートに使いません。
2. PCG 色コードの下位ニブル 0 は透明です。非ゼロのコードは COLOR と結合して
   256 色共有パレットを引きます。
3. SP/BG 内部は走査線ごとに合成し、`PRW=01` → BG1 → `PRW=10` → BG0 →
   `PRW=11` の順で背面から描きます。同じ PRW のスプライトは低番号が前面です。
4. SP/BG を一つのレイヤとして扱い、グラフィック／テキストとの前後関係は
   ビデオコントローラ R1 が決めます。
5. SP/BG の走査線出力は CRTC の有効表示解像度に従います。ホスト側の表示サイズを基準に
   座標やピッチを決めず、画面モード切替後も同じ VRAM／PCG 座標系を保ちます。

## 4. 構成とデータモデル

`x68k_bus_t::sp_ram` は `$EB0000–$EBFFFF` のフラットな 64 KiB 配列です。
`$EC0000–$ECFFFF` は未使用ミラーとして読み出し 0、書き込み無視とします。

| 領域 | アドレス | 内容 |
| --- | --- | --- |
| スプライト属性 | `$EB0000–$EB03FF` | 128 個 × 4 ワード |
| BG 制御・スクロール | `$EB0800–$EB0808` | BG0/BG1 の位置・表示・データ面 |
| 画面モード | `$EB080A–$EB0810` | 表示窓値と解像度設定 |
| PCG | `$EB8000–$EBBFFF` | 8×8 セル、16×16 パタン |
| BG データ | `$EBC000–$EBFFFF` | BG0/BG1 用の各 64×64 エントリ |

`sprite_scene_t` は `$EB0810`／`$EB0808` から導く描画用の一時記述子です。
BG パタンサイズ、実画面サイズ、BG1 可否、表示状態、各 BG のスクロールとデータ面を持ちます。

## 5. レジスタと動作仕様

### 5.1 スプライト属性と PCG

各スプライトは XPOS、YPOS、VR、HR、COLOR、SPAT#、PRW を持ちます。スプライトは常に
16×16 で、表示座標は `(XPOS - 16, YPOS - 16)` を左上とします。VR/HR はパタンを反転し、
`PRW=00` は非表示です。

PCG は 8×8 の 4 bpp セルです。16×16 パタンは連続する 4 セルを
左上・左下・右上・右下の順に組み合わせます。BG のエントリは VR、HR、COLOR、PCG# を持ち、
64×64 パタン面を球面スクロールします。

### 5.2 BG 制御（`$EB0808`）

| ビット | 意味 |
| --- | --- |
| bit9 | DISP/CPU。0 なら SP/BG レイヤ全体を表示しない |
| bit3 / bit0 | BG1 / BG0 の表示 ON |
| bit5–4 / bit2–1 | BG1 / BG0 のデータ面選択。各フィールドの下位ビットを使用 |

BG0 は BG1 より常に前面です。水平 512 ドット系では BG0 だけを使用し、
水平 256 ドット系では BG0 と BG1 を使用できます。

### 5.3 解像度設定（`$EB0810`）

本レジスタは CRTC R20 下位バイトと同じビット配置で扱います。

| ビット | 意味 | ix68k の扱い |
| --- | --- | --- |
| bit0 | H-RES（256/512） | BG 形状と BG1 可否を決定 |
| bit1 | H-RES 上位（768 系） | SP/BG を非表示 |
| bit2 | V-RES（256/512） | SP/BG 形状には影響しない |
| bit3 | V-RES 上位（1024 系） | SP/BG を非表示 |
| bit4 | L/H | SP/BG 形状には影響しない |

判定には下位 5 bit のみを用います。bit1 または bit3 が立つモードでは
スプライトコントローラは出力しません。512×256／256×512 は正規に扱い、H-RES のみで
16×16/8×8 BG と BG1 可否を決めます。

## 6. 描画とレイヤ合成

`x68k_sample_sp_codes_line()` が一走査線の SP/BG パレットコードを作り、
`x68k_render_sp_line()` が ARGB へ変換します。透明画素は前景合成では下地を保持し、
背景合成では黒を出力します。

`x68k_bus_get_screen_order()` は R1 の SP/TX/GR 優先順位から全レイヤの順序を返します。
R2 SON が 0 のときは、SP/BG レイヤ全体を非表示にします。

## 8. 互換性・既知の制約

- `$EB080A–$EB080E` による SP/BG と CRTC 表示窓のアライメント補正は未実装です。
- 実機のラインバッファ遅延、垂直帰線期間中のレジスタ更新制約は再現しません。
- 768 ドット系または 1024 ライン系では SP/BG を描きません。
- CRTC R20 と `$EB0810` の不一致は許容し、後者だけを SP/BG の正本とします。
