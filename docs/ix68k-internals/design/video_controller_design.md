# ビデオコントローラ設計

## 1. 目的と対象範囲

ix68k のビデオコントローラは、グラフィック／テキスト／スプライト-BG各レイヤの可視性・
優先順位・色変換・最終輝度を定めます。本書はその現行仕様を定めます。

- 対象: R1/R2、グラフィック／テキスト共有パレット、65536色パレット変換、
  システムポート#1のコントラスト、合成後の出力。
- 対象外: CRTC の走査タイミング・表示領域・スクロール、SP/BG内部の優先順位、
  R2半透明・特殊優先順位の詳細設計。
- CRTC が描画状態をラッチする時機は [`crtc_design.md`](crtc_design.md) を参照します。

## 2. 実装状態

| 項目 | 状態 | 補足 |
| --- | --- | --- |
| R1 の GR/TX/SP 優先順位 | ✅ | 3レイヤの前後関係を決定 |
| R2 の GS、TON、SON | ✅ | GVRAMページ、テキスト、SP/BGの表示を制御 |
| 16/256色パレット | ✅ | GRB555 生値と ARGB キャッシュ |
| 512ドット65536色パレット | ✅ | 上位／下位8bitパレットを再結合 |
| コントラスト | ✅ | 合成後に16段階の線形 LUT を適用 |
| R2半透明・特殊優先順位 | ✅ | AH、G/G、G/T、B/P=0を含む |

## 3. 設計の要点

1. レイヤ内部（SP/BG、GVRAMのページ）を合成した後、R1 が GR/TX/SP-BG の順序を決めます。
2. R2 は各グラフィックページ、テキスト、SP/BGの表示可否と特殊表示を制御します。
3. パレットの生値は GRB555 で保持します。通常の16/256色ではエントリを直接使い、
   65536色では同じ512バイトを二組の8bit変換表として再解釈します。
4. コントラストは各レンダラではなく、合成済み ARGB 行に一度だけ適用します。

## 4. パレットと色変換

`$E82000–$E821FF` は16/256色では256個の GRB555 エントリであり、テキストとSP/BGで共有します。
色インデックス0ではなく、パレット生値が`0x0000`であることを下位レイヤへの透過条件とします。

512ドット65536色では同じ512バイトを、GVRAM色コードの上位8bit用・下位8bit用の
二組のパレットとして使います。下位パレットは`$E82000`、上位パレットは`$E82002`から4バイト
周期で配置されます。`pal_raw[256]`から次で導出します。

```
L[k] = kが偶数 ? pal_raw[k & ~1]の上位バイト : pal_raw[k & ~1]の下位バイト
H[k] = kが偶数 ? pal_raw[k |  1]の上位バイト : pal_raw[k |  1]の下位バイト
GRB = (H[color >> 8] << 8) | L[color & 0xff]
```

この変換は65536色描画へ適用する（65536色は512ドット以下のみ。1024ドットでは出ない）。
未対応のR2特殊表示経路では正しい色コード生成・変換が未実装です。GRB555の輝度ビット I は
現在のARGB変換では反映しません。

## 5. レイヤ制御と合成

R1 は GR/TX/SP の各2bit優先値から、背面から前面への描画順を導出します。同値・禁止値を含む
値には既存互換のフォールバック順を用います。R2 は GS4–0でGVRAMページを、TON(bit5)で
テキストを、SON(bit6)でSP/BGを表示・非表示にします。SON とスプライトコントローラの
`$EB0808` DISP/CPU は論理積です。

R2 特殊表示時だけ、各レイヤから生色コードを採取して GRB555 として解決します。通常経路は
ARGB 合成を維持します。AH はテキストパレット0番との強制半透明、G/G はセカンドGVRAMページ、
G/T は R1 上でグラフィックより背面にある TX/SP-BG 合成結果を相手とします。複数の相手は
順に1/2合成し、3画面を均等には混ぜません。

半透明は各 GRB555 成分を `(front + back) >> 1` で丸め、Iビットは背面から引き継ぎます。
半透明後の黒は不透明です。G/G のセカンドページは通常表示の GS ゲートがOFFでも合成入力にします。
特殊優先順位では、領域内のベースGVRAM画素だけを TX/SP-BG より前へ昇格します。

R2 bit10 B/P は領域指定源を選びます。B/P=1 はベース生コードのbit0、B/P=0 はパレット出力の
bit0（カラーLSB）を使います。B/P=0では16/256色のベース選択時にコード0を透過候補として先に除外し、
65536色では上位／下位パレット解決後の出力を使います。これは mint.x の疑似半輝度に必要です。

## 6. コントラスト

システムポート#1 `$E8E001` の下位4bitはコントラスト値で、`0` は黒、`15` は最大輝度です。
ix68k は目標値を即座に読み出しへ反映し、描画値はフレーム先頭ごとに45段階の現在値へ追従させます。
各RGB成分には参照実装に基づく線形 LUT を適用します。

起動直後は `$0F` とし、SRAM `$ED0028` の既定 `$0E` をIPLROMが書くと定常値は14/15となります。
IOCS `_CONTRAST` はROMへ委譲し、システムポート書き込みの結果が描画へ反映されることで機能します。

## 7. 実装上の対応

| 役割 | 主な実装箇所 | 責務 |
| --- | --- | --- |
| パレット・R1/R2派生値 | `src/peripheral/crtc.c` | 生値、ARGBキャッシュ、表示／順序API |
| MMIO | `src/bus/x68k_bus.c` | パレット・ビデオ／システムポートの読書き |
| 通常合成・コントラスト | `src/render/compose.c` | レイヤ合成後のLUT適用 |
| GVRAM色変換 | `src/render/` | 65536色パレット解決 |
| R2特殊表示 | `src/render/compose.c` | 生コード経路の解決 |

`crtc_t` がパレットとコントラストのキャッシュを保持するのは実装上の所有であり、
ハードウェア上の責務分離を意味しません。

## 8. 互換性・既知の制約

- Iビットの輝度差、R2のYS/VHT（外部ビデオ入力）は未対応です。
- コントラストの物理的なカーブは未確定で、線形スケールは XEiJ に基づく近似です。
- `$E8E001` の上位4bit読出しと、システムポートの広域ミラーは未検証です。
