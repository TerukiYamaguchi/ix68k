# CRTC 設計

## 1. 目的と対象範囲

ix68k における CRTC（`$E80000`）は、表示領域、走査線進行、テキスト／
グラフィックのスクロール、CRTC 動作ポート、および描画状態のラッチ時機を管理します。
本書はその**現行の実装仕様**を定めます。

- 対象: CRTC R00–R23、CRTC 動作ポート、ラスタ駆動、描画状態のラッチ時機。
- 対象外: ビデオコントローラ R1/R2、パレット、コントラスト、半透明
  （`video_controller_design.md`）、スプライトコントローラ、各ソフトの不具合調査。
- 制約: CRTC の各周期を完全再現するものではありません。表示・割り込み・描画に影響する
  観測可能な状態を、CPU サイクルに同期した走査線モデルで再現します。

レジスタごとの対応状況は常に
[`crtc_support.md`](../support/crtc_support.md) を正本とします。

## 2. 実装状態

| 項目 | 状態 | 補足 |
| --- | --- | --- |
| R00–R07 による走査線・表示期間 | ✅ | 妥当な値のときラスターモデルに反映 |
| R09 ラスタ割り込み位置 | ✅ | MFP GPIP6/CIRQ に接続 |
| R10–R19 スクロール | ✅ | X はライブ、Y は V-DISP 開始でラッチ |
| R20 による表示モード | ✅ | 幅は R02/R03、縦方向は R20 と一部 R06/R07 を使用 |
| R21–R23、動作ポート | ✅ / 🔄 | ラスタコピー・高速クリアを実装。一部タイミングは近似 |
| 描画状態のラッチ | ✅ | パレットは V-DISP 開始でラッチ。色変換・コントラストはビデオコントローラが担当 |
| インターレースのフィールド交互表示 | ❌ | 表示高さは導出するが、フィールド単位の描画は未対応 |

## 3. 設計の要点

1. **可視幅は R20 の HD ビットではなく R02/R03 から決めます。**
   `R03 - R02` を文字クロック数として 8 倍します。非標準の正方形ドット設定でも、
   これが実際の可視幅に対応します。
2. **CRTC とスプライトの表示可否を混同しません。** スプライト／BG のモード・表示可否は
   スプライトコントローラの `$EB0810`／`$EB0808` が正本であり、CRTC R20 を
   そのゲートに使いません。
3. **縦方向の描画状態は V-DISP 開始で固定します。** R11 とグラフィック Y スクロール、
   パレットはその時点の値を当該フレームの表示に用います。R10 とグラフィック X
   スクロールは各行描画時点のライブ値です。
4. **GVRAM のページ構成は色モードで決まる。** 512 ドット時のページは各 512 KiB の
   連続領域であり、スクロールレジスタの対応も色モードごとに異なります。

## 4. 構成とデータモデル

`x68k_bus_t` が MMIO の生値 `crtc_regs` と VRAM を所有し、`crtc_t` が以下の
派生状態を所有します。

| 状態 | 更新タイミング | 用途 |
| --- | --- | --- |
| `x68k_raster_t` | フレーム開始・CPU サイクル進行 | 現在ラスタ、V-DISP 範囲、縦状態ラッチ |
| ラッチ済みパレット | V-DISP 開始 | ビデオコントローラが当該フレームの描画に使う値 |
| `rapid_clear_pending` | 高速クリア後の読出し | 動作ポート bit1 の完了通知 |

描画側はバス API からスクロール、ページ、パレットを取得します。CRTC は画素合成を
直接行いません。GVRAM／TVRAM／スプライトの合成は `src/render/` の責務です。

## 5. インターフェース／レジスタ

### 5.1 表示タイミングと表示サイズ

| レジスタ | 用途 | ix68k での使い方 |
| --- | --- | --- |
| R00–R01 | 水平トータル／同期 | MFP GPIP7 (H-SYNC) の位相計算 |
| R02–R03 | 水平表示開始／終了 | `R03 - R02` から可視幅を算出 |
| R04–R07 | 垂直トータル・同期・表示期間 | ラスターモデルの妥当性判定と V-DISP 範囲 |
| R09 | ラスタ番号 | MFP GPIP6 (CIRQ) の発生位置 |
| R20 | モード | 縦表示モード、ドット幅、GVRAM モードの補助情報 |

R20 ワードが完全に 0 の起動直後は、表示サイズを 512×512 にフォールバックします。
幅 1024 のモードは R06/R07 の差から 424／848 行を導出します。R20 の VD 値だけでは
この区別を表せないためです。

### 5.2 スクロールと GVRAM ページ

スクロール値は各レジスタの下位 10 bit を使います。テキストは R10 (X) と R11 (Y)、
グラフィックは R12–R19 です。

| 色モード | 表示ページ | ページ領域 | スクロール |
| --- | --- | --- | --- |
| 16 色・512 ドット | 4 | `$C00000 + n * $80000` | page n: R(12+2n) / R(13+2n) |
| 256 色・512 ドット | 2 | page0=`$C00000`、page1=`$C80000` | page0: R12/R13、page1: **R16/R17** |
| 65536 色・512 ドット | 1 | `$C00000` | R12/R13 |
| 1024 ドット | 1 | GVRAM 2 MiB を一面として扱う | R12/R13 |

512 ドット時のページ間優先順位と可視性はビデオコントローラ R1/R2 が決めます。
`x68k_bus_get_gvram_pages()` は、描画に必要なページ記述を前面順で返します。

16／256 色の GVRAM では、色インデックスが 0 かどうかではなく、対応する
パレットレジスタの生値が `0x0000` かどうかで下位ページへの透過を判定します。

### 5.3 CRTC 動作ポート

| ビット | 機能 | ix68k の仕様 |
| --- | --- | --- |
| bit1 | グラフィック高速クリア | 選択ページの表示高さ分を Y スクロール込みで消去します。消去自体は書込み時に一括実行し、完了 bit は次の読出しまで保持します。 |
| bit3 | テキストラスタコピー | R22 のコピー元からコピー先へ、R21 CP で選んだ TVRAM プレーンを 1 ラスタブロック単位でコピーします。bit が 1 の間は各水平フロントポーチでも実行します。 |

高速クリアは、実機の「V-DISP 開始後に行単位で進む」時間経過を再現しません。その代わり
ソフトウェアが観測する完了ポーリングと、対象範囲・スクロールの効果を保ちます。

## 6. 動作仕様

### 6.1 フレームと走査線

フレーム開始時に `x68k_bus_crtc_raster_frame_start()` が R04–R07 と表示高さから
走査線パラメータを導出します。有効な値でなければ既定の 567 行モデルへ退避します。
CPU の実行サイクルに応じて `x68k_bus_crtc_raster_advance()` が到達した走査線を
まとめて発火し、フレーム末尾は `x68k_bus_crtc_raster_flush()` が残りを消化します。

V-DISP 開始行では、縦スクロールとパレットをラッチし、V-DISP 終了行では MFP に
通知します。インターレースで同じ表示行に複数ラスタが対応する場合、最初のラスタだけを
描画対象とします。

### 6.2 描画状態のラッチ

パレットは書込み時に生値・ARGBキャッシュを更新し、既定では V-DISP 開始でラッチした値を
当該フレームの描画に使います。`-raster-pal live` は調査・互換性確認用にライブ参照へ切り替えます。
パレットの構造、R1/R2、コントラストの色変換は `video_controller_design.md` が定めます。

### 6.3 ラスタ同期合成

CRTC は CPU サイクルからフレーム内の絶対ラスタを導出し、到達した表示行をその場で合成します。
ライン数はフレーム内サイクルから直接求め、行ごとの整数除算を累積しないため位相ドリフトしません。
CPU が STOP/HALT 中でもフレーム終端では残りの行を flush し、各表示行を必ず一度だけ確定します。

描画状態は次の粒度で読みます。

| 状態 | 粒度 |
| --- | --- |
| テキスト／GVRAM の X スクロール、R1/R2、SP/BGレジスタ | 行ごとにライブ参照 |
| テキスト／GVRAM の Y スクロール、パレット | V-DISP 開始でラッチ |
| BG の X/Y スクロール | 行ごとにライブ参照 |

これにより、ラスタ割り込み中のスプライト位置、横スクロール、BGスクロール、R1/R2の書換えを
同一フレームの後続帯へ反映します。ラスタパラメータが不正なときは、従来のフレーム一括合成へ
フォールバックします。

| 役割 | 主な実装箇所 | 責務 |
| --- | --- | --- |
| CRTC 状態 | `src/peripheral/crtc.h` | `crtc_t` とラスタ状態の保持 |
| CRTC 派生値・動作 | `src/peripheral/crtc.c` | 表示サイズ、スクロール、ページ、ラスタ、クリア、コピー、描画状態ラッチ |
| MMIO 読書き | `src/bus/` | `crtc_regs` と CRTC 動作ポートの入出力 |
| 行単位レンダリング | `src/render/` | CRTC API を用いた GVRAM／TVRAM／各レイヤの合成 |
| MFP 連携 | `src/peripheral/mfp.c` | H-SYNC、V-DISP、CIRQ の通知処理 |

## 8. 互換性・既知の制約

- CRTC のクロック、同期信号、動作ポート bit1 の消去時間をサイクル精度では再現しません。
- R08 は保持のみで未使用です。
- 1024 ドットのインターレースは表示高さの導出までで、偶数／奇数フィールドの交互描画は未対応。
- 65536 色における 4 バンク独立スクロールによる色ずらしは未対応。
- ラスター有効性を満たさない非標準レジスタ値では、既定走査線モデルにフォールバックします。
