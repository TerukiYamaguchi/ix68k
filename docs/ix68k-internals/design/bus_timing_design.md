# バスアクセス時間設計

## 1. 目的と対象範囲

本書は ix68k における CPU のメモリ／MMIO アクセス時間を定めます。対象は、命令の公称
サイクル（mc68000 側）へ加算する、アドレス領域ごとのバス待ち時間です。

- 対象: メイン RAM、ROM（IOCS ROM、CGROM、SCSI ROM を含む `$F00000` 以降）、SRAM、GVRAM、
  TVRAM、スプライト VRAM／BG、CRTC、MFP、OPM を含む MMIO の CPU アクセス待ち時間。
- 対象外: 命令内部の公称サイクル、DMAC 転送量に応じた時間、OPM の BUSY 状態、CRTC
  の走査・ラスタコピーの進行、音声・タイマの実時間進行。
- この文書の値は、特記しない限り「CPU のアクセスに追加されるウェイト」です。資料の
  実測所要時間・命令全体のサイクル数・バスウェイトを混同しません。
- wait profile は少なくとも 10 MHz X68000、16 MHz XVI、X68030、060turbo 等の高速 CPU
  増設で分離します。ある系統で測定した値を別系統へ流用しません。
- wait の単位は、その profile の CPU クロック 1 周期とします。加算先は mc68000 コアが
  アクセスごとに前提とする公称バスサイクルであり、資料の「ウェイト数」「`TST` 所要時間の
  差分」が何クロックのバスサイクルに対する追加かは profile ごとに明記する（5 節）。
  公称バスサイクルと実機の差（例: ROM の非同期バス基本時間）は `cpu_design.md` の
  既知の制約であり、本書の領域別 wait へ吸収しません。

RAM/ROM と MC68030 キャッシュの既存方針は [`cpu_design.md`](cpu_design.md) を正本とし、
本書は VRAM／MMIO を含む全体の対応表を補います。

「値と区分」の区分は 5 節の `実機実測`、`資料記載`、`参照実装の近似`、`推定` と同じ意味で使います。

`推定` として根拠を記載します。

`✅` は ix68k が実機の全ての微細な遅延を再現するという意味ではありません。RAM の通常経路で
追加課金をしないという現行方針が実装済みであることを示します。

状態記号の凡例: `✅` は現行方針で実装済み、`🔄` は推定値または近似値で実装済み（値の区分は
「値と区分」列に従う）、`❌` は未実装（wait=0 のまま）。5.2 節の推定値を実装した領域は、
実機計測で置換するまで `✅` にせず `🔄` とします。

## 3. 資料の読み方

### 3.1 10 MHz X68000 の周辺デバイス

XEiJ の公開ソースは、初代、ACE、ACE（第2版）、PRO、XVI の実機で `TST` を実行した
所要時間を掲載し、その差分を待ち時間へ換算しています。X68000 10 MHz 向けの換算値は次の
とおりです。

| 対象 | 換算 wait | 備考 |
| --- | ---: | --- |
| メイン RAM | 0.123 | DRAM リフレッシュを 1/8 cycle/word とする平均近似 |
| GVRAM | 1.145 | `TST.W $C00000` の実測差分 |
| TVRAM | 2.046 | `TST.W $E00000` の実測差分 |
| CRTC | 1.050 | R00 および動作ポートはほぼ同値 |
| ビデオコントローラ・パレット | 2.668 | モードレジスタは 0.592 と別値 |
| MFP | 4.332 | GPIP の byte read を測定 |
| OPM | 1.715 | status の byte read を測定。書込みや BUSY 待ちを示さない |
| DMAC | 14.853 | ch0 CSR の byte read を測定 |
| SCC | 6.025 | chB RR0 の byte read を測定 |
| RTC | 1.718 | onesec の byte read を測定 |
| プリンタポート／システムポート | 1.060／1.058 | PRN data、SYS contrast の byte read を測定 |
| ADPCM、FDC／FDD、HDC、PPI、I/O コントローラ | 1.710–1.716 | OPM status とほぼ同値 |
| BG／スプライトレジスタ | 1.051 | `TST.W $EB0800` を測定 |
| SRAM／ROM | 1.057／1.055–1.058 | SRAM と CGROM／IPL ROM。XEiJ 近似では CPU wait 無効時も維持する |

X68030 と 060turbo の換算値は、`TST` 所要時間表の main memory 行との差分をクロック周期で割った
値である（X68030 の GVRAM は (0.4951−0.2400)÷0.04=6.38、060turbo の GVRAM は
(0.4700−0.0399)÷0.02=21.5 で一致を確認した）。10 MHz 機の換算値は、5 機種平均の差分に RAM 分
0.123 を加えても再現できない（DMAC 14.851、SCC 6.029 はほぼ合うが、OPM は 1.813 対 1.715、
モードレジスタは 0.495 対 0.592、MFP は 4.267 対 4.332）。導出は不明で、無ウェイトのバスサイクルを
基準にした値と考えられる（未確認）。表の XVI 列は、main memory 行が 1.650 µs（10 MHz の約 16
クロック）であることから 10 MHz 動作での測定と考えられる（未確認）。機種差は小さいが、ビデオ
コントローラのモードレジスタの `TST` 所要時間は初代・ACE の 1.641 µs に対し PRO は 1.770 µs、
XVI は 1.733 µs と異なります。本書は XEiJ の換算値を使い、機種別には持ちません。

これは X68000 の固定的な周辺バスの遅延を表す有用な測定記録であり、X68030 のような
ソフトウェア設定可能な wait ポートはありません。ただし、XEiJ の換算値自体は機種差、アクセス幅、
表示状態、バス位相を完全には表しません。厳密な生の wait 数ではなく、ix68k の初期プロファイル
候補として扱います。

### 3.2 XVI（68000、16 MHz）

XVI は 68000 系だからといって 10 MHz 機と同じ wait profile にできません。CPU は 16 MHz、
Outside X68000付録回路図で確認できる DMAC 入力と拡張 I/O スロットは 10 MHz です。CRT／内部 I/O を含む各信号系は
別途確認が必要であり、CPU クロックだけを 10 MHz の換算 wait に掛ける単純換算は根拠になりません。
ただし実装には数値が必要なため、5.2 節では「デバイスのアクセス時間が絶対時間で一定」という
仮定（推定）のもとに、公称バスサイクルの短縮分を含めた式で暫定値を置きます。

現時点では、XVI の各 MMIO／VRAM 領域に対する生 wait を裏付ける表を未確認です。XVI の
profile を導入する際は、少なくとも 10 MHz X68000 と同じベンチを 16 MHz 動作で測定し、
GVRAM、TVRAM、MFP／OPM 等を個別に決めます。DMAC と拡張 I/O はさらに別のバスドメインとして
検証します。

### 3.2.1 母機、CPU クロック、メインメモリ

wait profile は CPU の MHz だけで決めず、少なくとも X68000 系と X68030 系の母機を区別します。
040turbo／060turbo のようなアクセラレータは X68030 系の母機構成として記録し、母機と
アクセラレータの組合せを profile のキーにします。この二大別は周辺機器のアクセス時間を一律化する
ものではなく、各領域の変換回路・バス位相・read/write 別の値は profile ごとに保持します。

標準機の CPU クロックは X68000 系が 10 MHz または 16 MHz、X68030 が 25 MHz です。
REDZONE の 24 MHz、040turbo／060turbo の 50 MHz、060turbo の 75 MHz は対応構成として
検討対象に含めるが、本書が wait 値を有効化する前に、基板版・設定と一次資料を対応付けます。
非公称クロックを既存 profile の単純な倍率として扱いません。

XVI は 10 MHz と 16 MHz の動作クロックを切り替えられるとされるが、この点は本書では
一次資料と照合していない（未確認）。profile のキーには母機とアクセラレータに加え、動作
クロックの設定を含め、10 MHz 動作の XVI は 10 MHz X68000 の値を流用せず別 profile として
扱う（5.2 節の XVI 推定値は 16 MHz 動作の場合）。X68000 Compact がどの profile に入るかも
未確認であり、資料と照合するまで profile を割り当てません。

メインメモリの容量構成と CPU アクセス wait は分けて扱います。10 MHz X68000 の通常 RAM は追加 wait
なしとします。XVI は内部増設で最大 8 MB、残る最大 4 MB は拡張スロットのメモリボードで構成できるとされるが、この容量は一次資料と未照合（出典なし、推定）です。
後者は拡張スロット経由であるが、実際のアクセス時間は装着ボードとバス位相に依存するため、
容量だけから「10 MHz 機相当」の wait を固定しません。X68030 は内部最大 12 MB を搭載できるとされるが（同じく出典なし、推定）、
DRAM wait は System Port #5 の設定とページ境界に従う（3.6 節）。

DRAM リフレッシュは実在するが、現行の固定 wait profile では個々のリフレッシュ周期をモデル化
しません。RAM のノーウェイトはこの平均化の近似であり、リフレッシュ遅延が存在しないという主張ではありません。

グラフィック VRAM と大部分の I/O デバイスには X68000 系からの流用がある一方、TVRAM を含む
全領域が物理的・時間的に同一であることは前提にしません。高速 CPU／アクセラレータでも、これらの
外部領域は CPU RAM より遅い候補であり、10 MHz 相当という一般化ではなく、資料または実測に基づく
領域別 wait を適用します。X68030 の DMAC は X68030 Inside/Out付録回路図で確認できる入力クロックが
12.5 MHz です。ただし、
入力クロックは CPU MMIO アクセスの wait や実効 DMA 転送速度と同義ではありません。

### 3.3 X68030 の周辺デバイス表

*X68030 Inside/Out* p.135、図14「各デバイスアクセス時のウェイト数の実測値」は、
17 回連続アクセスの平均として次を掲載します。測定に使った命令とアクセス幅は本書では未確認
であり、wait の基準サイクル（5 節）とともに実機ベンチで確認します。3.1 節、3.4 節、3.5 節の
XEiJ の数値は、ローカルの XEiJ_0260608 の `XEiJ.java`（`mpuSetWait()` 周辺の計時表と換算表）と
照合済みです。図14 の値は書籍が手元になく未照合です。

図14 の値は、同じ領域の XEiJ の X68030 換算値より大きい。差は CRTC・DMAC・SCC で約 3、GVRAM で
約 2.6、OPM で約 4.3、MFP で約 4.7 クロックです。この差の原因は未解明です。
`cpu_design.md` が引く同書 p.130-131 の「ウェイト数」は、3 クロックの非同期基本サイクルを
除く数え方（ROM `$0` は 5 クロック＝3＋2 ウェイト）であり、「図14 が基本バスサイクル分を含む」
という説明とは矛盾し得ます。したがって図14 は「資料記載、基準未確認」として生のまま使い、
図14 に行がない領域は XEiJ 値に経験的な差（約 3）を加えて寄せます。この差は説明のない経験則です。

| デバイス | read | write |
| --- | ---: | ---: |
| VRAM（本文の導入から GVRAM と読む） | 9 | 9 |
| CRTC | 9 | 9 |
| ビデオコントローラ | 9 | 11 |
| DMAC | 37 | 31 |
| MFP | 24 | 24 |
| OPM（FM 音源） | 19 | 53 |
| SCC（RS-232C） | 41 | 49 |
| スプライト VRAM | 17 | 18 |

表は TVRAM を独立した行にしていません。したがって GVRAM の 9 を TVRAM の確定値として
流用してはなりません。また DMAC／SCC などは約 600 ns から 1 µs 超まで変動すると本文にあり、
位相を持たない固定 wait モデルでは平均値にとどまる。

### 3.4 TVRAM

XEiJ の公開ソースには、実機で `TST.W` を実行した時間の表と、その値に基づく近似があります。
10 MHz X68000 向けの近似は GVRAM=約1.1・TVRAM=2、X68030 向けの近似は
GVRAM=6・TVRAM=7（換算値 6.377／6.623）です。ただし XEiJ 自身が機種差、アクセス方法、表示状態を考慮しない
近似であると明記します。

XEiJ の X68030 値は図14 より小さい基準であるため、図14 の GVRAM=9 と並べる TVRAM は
補正した 9（推定、5.2 節）とします。TVRAM は確定仕様ではなく、実機で read/write、表示期間／
垂直帰線期間、同時アクセスとラスタコピーの有無を分けて測定するまで区分は `推定` または
`参照実装の近似` のままとします。状態記号は 2 節の凡例に従います。

### 3.5 060turbo（X68030 母機 + 50 MHz MC68060）

060turbo は X68030 の MC68EC030 を MC68060 へ換装するアクセラレータです。CPU は 50 MHz
になる一方、マザーボード側の VRAM／I/O は X68030 のものを使うため、X68030 の 25 MHz 値を
そのまま使うのではなく、68060 と周辺バス変換の組合せとして profile を持つ必要があります。

XEiJ は 50 MHz 060turbo 向けの近似として、GVRAM／CRTC／ビデオコントローラ／スプライト
コントローラ=21、TVRAM=22、パレット=33、OPM 等の通常 I/O=37、MFP=47、DMAC=73、RTC=77、
SCC=97、プリンタ／システムポート=17、SRAM=13 wait を置く（OPM 等の通常 I/O=37 は ADPCM、FDC／FDD、HDC、PPI、I/O コントローラを含む）。これは XEiJ の実機 `TST` 計時に基づく候補値であり、特に
060turbo は I/O ポート書込みの待ちの間にも多数の命令を実行し得るため、XEiJ 自身もこの
オーバーラップを未考慮と注記します。よって ix68k では「50 MHz だから X68030 の値を 2 倍」
とはせず、上記を初期候補に実機ベンチで検証します。

### 3.6 X68030 RAM／ROM

System Port #5 の bit7–4 は ROM wait、bit3–0 は DRAM wait です。設定値は原則として
`+2` wait だが、DRAM 設定 `$0` はスタティックカラム中 0 wait、ページ跨ぎ 4 wait となります。
`$4` は 6 wait（16 MHz 相当）、`$a` は 12 wait（10 MHz 相当）です。
「16 MHz 相当」「10 MHz 相当」は資料上の呼称と考えられ（推定）、時間として等価ではありません。
25 MHz で 3+6=9 クロックは 360 ns であり、16 MHz 機の 4 クロック（250 ns）とは一致しません。

ix68k の現行実装は、ページ継続を追跡せず DRAM `$0` を 0 と近似します。ROM の非同期バス
基本時間も含めた残差などは `cpu_design.md` の既知の制約です。

### 3.7 060turbo 向け遅延ツールの適用範囲

`060opmp` と `060prnp` は、060turbo の 68060 モードで MMU fault を利用し、FM 音源または
プリンタの特定ポートへ約 6 µs のソフトウェア遅延を追加するツールです。この値は汎用の
VRAM／MMIO wait 表ではありません。特に `060opmp` が記す X68030 の約 1.2 µs のハードウェイトは
FM 音源アドレスレジスタへの書込みについての観測であり、データレジスタの read/write や他の
OPM レジスタへ一律に適用しません。X68030 の連続アクセス平均表と併用する場合も、アクセス対象・
幅・位相を記録して検証します。

## 4. 現行実装

`src/bus/x68k_bus.c` の `bus_access_timing()` は mc68000 の `access_timing` フックです。

ユーザー向けの設定名は `series`（内部識別子は `x68k_timing_profile_t`）で、`x68000`（既定）、
`xvi`、`x68030` を選べます。設定ファイルの `series =` または `-series` で指定します。
X68030 専用の CPU アクセラレータは `accelerator = 060turbo | 040turbo`（CLI は `-accelerator`、
既定 `none`）で指定し、`series = x68030` のときだけ許可します。`060turbo` は 68060/50MHz、
`040turbo` は 68040/25MHz（既定）または 33MHz に限る。040turbo の実測値はまだないため、wait 表は
X68030 母機の値を暫定で流用する（クロックの一次資料も未確認）。
バス wait の無効化は `series` とは別に `bus_timing = off`（CLI は `-bus-timing off`）で指定します。

- `bus_timing = off` はすべてのアクセスを cacheable=false、wait=0 とする計測・デバッグ専用で、
  内部では `X68K_TIMING_PROFILE_NONE` になります。`series` は無視されます。
- 機種 profile は RAM、ROM、SRAM、VRAM、各 MMIO と sprite 領域を領域別・read/write 別に
  分類し、5.2 節の値を返します。`x68030` と `060turbo` の RAM/ROM は Port #5 の値を使います。
  `x68000-10` と `xvi-16` の long はワード値の2倍、X68030/060turbo の long は表の値をそのまま使います。

profile と CPU の組合せは起動時に検証します。`x68000-10`/`xvi-16` は 68000、`x68030` は
68EC030/68030、`060turbo` は 68060 にだけ選択できます。`bus_timing = off` は全モデルで選べます。

`fc=7`（CPU 空間）のアクセスは、領域判定の前に cacheable=false、wait=0 で返します。
コアは MC68030 のコプロセッサ CIR アクセスを `fc=7` と CPU 空間アドレス
`CP_SPACE_BASE(0x20000) | cpid<<13 | cir`（FPU では `$22000+cir`）の組で `access_timing` へ
渡す（`extern/cmc68000/src/cpu/coproc.c`）。このアドレスは常に低位で、内蔵 FPU モデルへの
アクセスも同じ fc=7 のバスサイクルとして数えられる（`cpu_internal.h` の
`cpu_account_bus_cycle()`）。修正前は FC を見ずに `physical & 0xFFFFFF` を RAM 上限と比較して
いたため CIR が RAM と誤分類され、DRAM 設定が 0 以外のときに CIR write（と CACR の ED=0 の
CIR read）へ DRAM wait が加わってきました。`tests/wait_profile_test.c` が回帰を確認します。
CIR アクセスに実機でボード上の wait があるかは未確認で、無課金は資料に基づく値ではありません。
060 の高位ローカルメモリは 24-bit マスク前に識別し、profile にかかわらず無課金で返します。

MFP や OPM の機能上の時間進行と、ポートを `MOVE` したときの profile wait は別物です。
OPM の BUSY はデバイス状態であり、X68030 profile の OPM write=53 と同じものではありません。

## 5. 実装時の推定値ポリシー

wait profile の実装を開始した時点で、対象 CPU／マシン profile の VRAM／MMIO を一律 `wait=0`
のまま残してはなりません。生の実測値が未確認の領域には、最も近いバスドメインの資料値から
推定した非ゼロ値を入れます。ただし推定値を実測値として扱いません。

各定数は本書の対応表へ、少なくとも次を記録します。

| 記録項目 | 内容 |
| --- | --- |
| 値と単位 | CPU access あたりに加える wait と、read/write・アクセス幅の適用範囲 |
| 単位クロックと基準サイクル | 値の単位とするクロックと、その値が加算される公称バスサイクル長。資料値の基準がコアの前提と異なる場合は差を記録する |
| 変換式と丸め | 資料値からフックへ返す整数への変換式。小数値は元の値と丸め後の値を両方記録する（丸め規則は 5.1 節） |
| 区分 | `実機実測`、`資料記載`、`参照実装の近似`、`推定` のいずれか |
| 根拠 | 書籍のページ／図、実機ベンチ、または導出に使った profile と式 |
| 適用 profile | CPU、マシン、アクセラレータ、必要なら表示状態 |
| 検証計画 | 実測で置換する条件と、差分を記録するベンチ |

推定の初期候補は次のとおりです。

| profile | 直接の資料がない領域の推定根拠 |
| --- | --- |
| 10 MHz X68000 | XEiJ の実機 `TST` 計時からの換算 profile。GVRAM 約1.1、TVRAM 約2、MFP 約4.3、OPM status 約1.7 等。write は測定がなく read と同値（推定）。 |
| XVI | 10 MHz X68000 値をそのまま流用せず、CPU=16 MHz、DMAC・拡張 I/O=10 MHz、CRT／内部 I/O は信号系ごとに確認したクロックの各ドメインに対応する値として導出します。導出式と仮定は 5.2 節に記録し、未測定だからという理由で 0 にしません。 |
| X68030 | *X68030 Inside/Out* の実測表を優先し、表にない領域（TVRAM、SRAM、RTC 等）は XEiJ の換算値を図14 の基準へ補正して `推定` とする（5.2 節）。 |
| 060turbo | XEiJ の 50 MHz 060turbo profile を初期候補にします。GVRAM=21（単純な同時間換算なら18になるが、XEiJ 実機計時由来の約21.5を優先）、TVRAM=22、MFP=47、通常 I/O=37、DMAC=73、SCC=97 等。 |

推定値は互換性上の安全な既定値ではなく、現状の 0 wait より実機の時間へ近づけるための暫定モデルです。実機計測が得られたら、根拠・値・影響した回帰結果を同じ表に追記して置換します。

### 5.1 実装設計と検証境界

- wait profile は物理的なマシン／アクセラレータ構成として明示的に選びます。CPU モデルや
  実行クロックだけから推定せず、ホスト側の速度設定とも分離します。X68010 を積んだ
  X68000 構成は本設計の対象外とします。
- X68030 の System Port #5 による RAM／ROM の既存近似と CACR の扱いを維持し、
  VRAM／MMIO の領域別・read/write 別の表とは分けます。`X68K_WAIT_MAX` の 31 は
  ポート値の有効ペナルティ用であり、フックへ返す VRAM／MMIO wait の共通上限にしません。
  例えば資料の OPM write=53 や SCC write=49 を 31 に切り詰めません。
- 領域判定は物理アドレスとアクセス種別を使います。FC=7 の CPU 空間は識別済み（4 節）。24-bit
  マスク前に 060 の高位ローカルメモリも識別し、低位アドレスの RAM／MMIO と誤認しません。未マップ
  領域にも隣接デバイスの wait を適用しません。フックはバスエラー、MMU テーブルウォーク、
  例外フレーム書込み、ベクタ読出しでも呼ばれるため、それらを通常の成功したオペランド
  アクセスと混同せず、アクセス先とコアの経路に応じた扱いを検証します。
- `access_timing` の 1 回はコアのバス callback 1 回に対応し、返却値はその単位の追加
  CPU サイクルです。非整列アクセスは複数回に分解され得ます。
- 68000 系 profile は 16-bit データバスのため、long オペランドは必ず 2 回のバスサイクルに
  なり、それぞれが wait を受けます。したがって long の課金総量は 1 ワードあたりの wait の
  2 倍とします。コアが `size=4` を 1 回の callback にまとめるか 2 回に分けるかは検証で確認し、
  総量がこの値になるよう返却値を決めます。68030 系はポート幅（8/16/32 bit）に依存するため、
  `size=4` の課金は領域ごとのポート幅を確認するまで未確定とし、一律に 2 倍しません。
- 資料値や XEiJ 換算値が小数の profile（10 MHz X68000 等）は、領域・read/write ごとに
  最近傍の整数へ四捨五入（0.5 は切り上げ）した値をフックへ返します。小数累積器は採りません。
  課金が直前までのアクセス履歴に依存すると、同一アクセスの結果が再現せず、検証と
  テストが困難になるためです。丸めは最終値でのみ行い、換算式の途中では丸め前の値を使います。丸めで失われる平均値の誤差（例: メイン RAM 0.123→0）は
  近似の一部として 5 節の記録項目に残します。
- 固定 wait は位相依存の平均近似であり、OPM BUSY や DMAC の転送時間そのものではありません。
  将来の走査・DMA・VRAM 競合を導入する際は、固定値に含まれる遅延との重複を整理し、
  二重計上を避けます。

検証では profile、領域、read/write、アクセス幅を組み合わせ、GVRAM と TVRAM、各 MMIO、
RAM／ROM、未マップ領域とその境界を確認します。ポート #5 と CACR の既存動作、FC=7、
高位ローカルメモリ、バスエラー、MMU／例外経路も回帰対象とします。ロングおよび非整列
アクセスはフックの呼出し単位と課金総量を確認し、実機ベンチで推定値を検証します。
PERF 計測基盤（性能チューニング用の仮想CPUサイクル計測）はモデル化済み wait を含む CPU 実行サイクルと仮想経過
サイクルを比較する手段として利用できるが、計測値だけで wait の実機精度を保証しません。

### 5.2 実装用の推定値

実装に数値が必要なため、根拠のある数値を持たない領域には `推定` の値を置きます。いずれも実測では
なく、実機ベンチで置換する前提の暫定値です。丸めは 5.1 節の規則（最近傍、0.5 は切り上げ、
最終値でのみ丸める）による。

**単位と基準サイクル。**
- 単位は各 profile の CPU クロック 1 周期とします。
- XEiJ の X68030 と 060turbo の換算値は、同一命令で main memory をアクセスした時間との差分で
  あり、RAM 側の wait を含まない（検算済み、3.1 節）。10 MHz 機の換算値の導出は不明で、
  無ウェイトの 4 クロックバスサイクルを基準にした値と仮定する（XVI の式はこの仮定に依存する）。
  図14 の値の基準は未確認である（3.3 節）。
- 公称バスサイクルは、68000 は 4 クロックと考える（一般知識。コアの前提との一致は未確認）。
  68030 は、mc68000 コアが I-Cache Case の 2 クロック（同期）を前提にしており、非同期デバイスでは
  1 クロック／アクセスの過小評価が残る（`cpu_design.md`）。この残差は 1 節のとおり領域別 wait へ
  吸収せず、本節の値にも含めません。68060 は未確認です。
- 推定の補正量は「最も近い図14 のデバイスを基準にした差」であり、各行に基準デバイスを記します。
  差は領域によらず一定という保証はありません。

**write の扱い。** XEiJ は read しか測定していません。特記しない限り write は read と同値とし、

**060turbo**（単位 50 MHz クロック、基準は XEiJ の差分）。XEiJ の値（`参照実装の近似`）を使う:
GVRAM=21、CRTC=21、ビデオコントローラのモード=21、BG／スプライトレジスタ=21、TVRAM=22、
パレット=33、OPM、ADPCM、FDC／FDD、HDC、PPI、I/O コントローラ=37、MFP=47、DMAC=73、RTC=77、
SCC=97、プリンタポート／システムポート=17、SRAM=13（CGROM、IPL ROM は 0）。GVRAM の換算値は
21.5 だが、XEiJ の整数の実装値 21 を使う（060turbo は換算値でなく XEiJ の実装値を採るため、
丸め規則の例外とする）。write は read と同値（推定）。メイン RAM とローカルメモリの区別は未設定（未決）。XEiJ 自身が I/O 書込み中の命令オーバーラップを未考慮と注記する（3.5 節）。
スプライト VRAM は XEiJ に値がないため推定とし、BG／スプライトレジスタ（21）に、図14 と
X68030 のレジスタ推定値 9 の差 8／9 クロック（25 MHz で 320／360 ns）を 50 MHz で換算した 16／18 クロックを加えて
**read=37、write=39** とします。

## 6. 今後の実装順序

1. CPU／マシン profile を選択する枠を用意し、10 MHz X68000、16 MHz XVI、X68030、060turbo
   等の高速 CPU 増設を分離します。
2. GVRAM と TVRAM を別領域として扱える wait profile を導入します。
3. X68030 の GVRAM は資料値 9、TVRAM は推定値 9 として実装し、後者を実測で検証・置換します。
4. MFP／OPM を含む MMIO は、まず X68030 実測表の平均値による固定モデルを検討します。
   位相依存の DMAC／SCC は固定値を正確な再現と称しません。
5. CRTC の走査位相、DMAC 所有、TVRAM の同時アクセス／ラスタコピー競合を導入する場合は、
   固定 wait の上乗せと二重計上しないよう、バス所有モデルとして設計します。

この順序は設計提案であり、実装の着手を意味しません。定数を有効化した後も、10 MHz X68000、
XVI、X68030、060turbo の実機で同一の read/write ベンチを測定し、推定値を置換します。
